The partial-coverage path derives identity from the unmodified contexts on both sides, including role values, and uses exact-key lookup to filter source rows and supply evidence to retained rows. With a configured mapping `builder → planner`, a retained recorded anomaly with role `planner` and the same source anomaly with raw role `builder` do not match. The source row is added while the recorded row is retained, so one anomaly appears twice in the mixed drawer, and source evidence is not attached to the retained row. The normal source path is real: `LiveService.HydrateWorkspaceEvents` derives anomalies from raw facts/source events (`service.go:923–927`); the recorded read projection maps anomaly roles in `aggregations.go:686–695`. This contradicts the accepted partial-merge contract and weakens provenance consistency. Compare on a canonical mapped representation while preserving each entry’s origin and displayed source facts. Existing unit cases cover exact-context partial merges but not equivalent raw/projected roles.
