Codex Transcript/readResponseItem currently records generic calls but drops call arguments and produces no skill or delegation facts. Thus Codex source facts cannot reach the existing auxiliary fact consumers. CLI generation, backfill and capture carry separate top-level auxiliary slices, with refresh rules that must become owner-aware. Frontend ledgerSkills/ledgerTaskLinks return only top-level collections.

## Ownership and representation

Expand the current schema 5 with a sequential 5-to-6 migration, after confirming no upstream schema owner has advanced it. AL-57 changes are already present at this baseline; inspect fetched main before freezing this number and coordinate any collision through a contract addendum, not an incompatible reuse.

SessionFact gains canonical Skills and TaskLinks collections. Each fact may carry source_event_id, source_message_id and source_invocation_id when explicitly available. A source call ID identifies the raw invocation occurrence, independently of metric InvocationFact rows. Session containment supplies the canonical session owner; projections expose session_id plus source harness and available finer identifiers. Facts without a source call ID remain session-owned and retain recorded turn/message positions. Do not fabricate IDs, timestamps, outcomes, errors, costs or skills. Preserve repeated equal-looking facts with distinct recorded occurrences.

For Codex, native function/custom tool call IDs establish invocation scope. Explicit skill tool/load records, or a positively identified completed skill-file read, can establish recorded loading evidence; listing skills, mentioning paths, announcing intent or receiving inherited context cannot. Record the kind of evidence and distinguish known loading outcome from unavailable skill execution outcome; analytics must not treat unknown execution outcomes as failures or successful execution. Native spawn_agent and supported recorded delegate tools establish delegation occurrences, while send_message/wait/followup alone do not establish a new spawn. Preserve the raw source output reference. Link a child UUID only from explicit source relationship evidence; task namespace alone must not be guessed into a UUID. An unresolved referenced child remains explicit and navigable as unavailable. Parent metadata proves hierarchy, not a delegation occurrence.

For OpenCode v1 and v2, the enclosing session, event ID, message ID and recorded tool call identity establish ownership. Preserve original values and statuses. Task facts remain owned by the parent that called task. A returned explicit child ID remains recorded even when child source data is unavailable; source-backed parent metadata can verify a relation but its absence must not erase a recorded reference.

Retain legacy top-level collections only as lossless unresolved compatibility history, with explicit ownership diagnostics. A legacy fact may relocate only when explicit owner/source identity proves its destination. Session-local indexes, names, role/model or timing are insufficient. Derive ticket/fleet projections from granular facts plus unresolved history; omit a transitional duplicate only with reliable shared identity. Value equality cannot erase multiplicity. New known facts must never be written twice as both canonical top-level and session facts. Omitted/empty collections remain valid. Ordinary reads and GET never migrate or rewrite files.

Expand compatible readers and migration first, then migrate producers, persistence and consumers together before publication. Preserve old ledger bytes/backups through the migration framework; rollback requires the preserved old representation or an explicit compatibility export because old binaries cannot consume the new canonical schema. Do not remove old reader compatibility during this ticket.

Refresh replaces facts only for explicitly and successfully refreshed owners, including authoritative empty snapshots. Preserve unavailable remote owners, missing roots, malformed/partial sources, other harnesses, unrelated roots, unresolved legacy history and prior trees. Successful partial extraction is not complete source coverage. Growing snapshots replace their own facts; unchanged refresh is stable. Missing source records produce incomplete/mixed-age diagnostics rather than silent deletion or invented zero. Heuristic identity recovery remains explicit opt-in. Cover both generate and backfill through save/reload and capture publication/history, not merely pure merge helpers.

## Architecture and delivery acceptance

Pure flattening, ownership and aggregation functions belong in domain with immutable value semantics and no I/O, clocks or mocks. Source decoding, validation, migration I/O, repositories, capture, CLI and HTTP remain boundaries. TypeScript uses strict types and runtime validation, with no any; Go contains no any/interface{}. No emojis. All facts remain visible without hydration, including unavailable/pending/failed/partial enrichment. Session views show only their owned facts and explicitly distinguish unresolved history. Ticket/fleet filters count occurrences once; success rate uses only proven relevant outcomes and reports unavailable otherwise.

Deliver owner/source identity in CLI/API, Skills & Subagents, timeline badges, child links, fleet analytics and comparisons. Use self-contained source-format fixtures, never live ticket files. Required verification includes focused ownership/multiplicity/migration/partial-refresh regressions, frontend tests and canonical build, embedded standalone assets and integrated make after merging origin/main. Parent owns integration, review consolidation, final telemetry, commits, push and PR publication. No agent merges the implementation PR.
