## Baseline and evidence

- Baseline: `1d20117711aab96a230679d3cdb9406853fe3f04`; initial Git status was clean. Ticket branch: `feat/AL-47-live-trace-dynamic-refresh-active-session-polling`.
- `.agenticlens-config.yaml` selects `alspaces`, backend polling at 2000 ms, active threshold 300 seconds, stall threshold 120 seconds, and recent-message buffer capacity 500. Preserve those settings and configurable backend cadence.
- `backend/internal/adapters/live/service.go`: `pollAndBroadcast` excludes tree refresh time when comparing trees. `broadcastTraceUpdates` already marshals and compares complete traces, but calls `GetSessionTrace` for every node every tick. `GetSessionTree` independently calls it again for anomalies. `GetSessionTrace` builds messages, tokens, parts, child references, recent errors, and anomaly output from read-only SQLite. It currently tolerates optional child-link lookup failure; preserve baseline trace visibility and do not introduce a new successful-empty lookup path.
- `backend/internal/adapters/live/sqlite.go`: message/part records expose optional `time_updated`; `FetchSessionTrace` handles schemas without those columns. Session time alone is not a sufficient content revision. Use a read-only source generation observation on a stable SQLite connection to avoid this assumption.
- `LiveService.GetSessionTree` derives `running` before the configured stall threshold, `stalled` until active threshold, otherwise `completed`; the frontend additionally accepts `active` as requested by the specification. Preserve this producer behavior.
- `backend/internal/adapters/http/live_handlers.go`: `LiveStreamHandler` already flushes SSE frames and unsubscribes on cancellation. Existing buffered broadcasts drop events when subscribers are slow, so REST recovery is necessary even while SSE reports connected.
- `web/src/views/LiveObservability.tsx`: trace selection uses a cleanup guard, but manual refresh lacks selection ownership protection; SSE sets trace state inside a selected-ID state updater; no active trace REST loop exists. `web/src/api/liveApi.ts` polls only trees during fallback.
- `web/src/components/LiveTraceInspector.tsx`: message items use stable IDs and own reasoning state; existing layout effect preserves scroll for increased message counts, with latest-first and oldest-first controls. Extend preservation to same-count content growth without changing ordering behavior.
- CLI grounding: `./bin/agentic-lens generate --help` could not execute because the binary is absent. `backend/cmd/agentic-lens/main.go` declares `--source`, `--nonce`, `--ticket-id`, `--ticket-title`, `--ticket-type`, `--json-output`, `--append`, and `--codex-home`. Parent must confirm built command help before final extraction. No build or application tests have run at the planning gate.
