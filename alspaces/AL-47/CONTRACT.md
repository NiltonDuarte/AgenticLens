# AL-47 Technical Contract

Approval: user explicitly approved implementation of this contract and iteration 01 plan on 2026-10-31. Baseline frozen.

## Problem and grounded scope

The selected live trace must stay current through SSE and REST fallback without replacing the inspector or interrupting reading. The source specification is `alspaces/plan/to-do/AL-47 live trace dynamic refresh and active session polling.md`.

The baseline already broadcasts `trace_update` in `LiveService.broadcastTraceUpdates`, consumes it in `LiveObservability`, and tests its delivery. The missing guarantee is active trace REST refresh, with protection against stale asynchronous results. `GetSessionTree` and `broadcastTraceUpdates` also reconstruct the same histories on every unchanged poll. This ticket strengthens those paths rather than introducing another transport.

## Acceptance boundaries

1. Selection fetches a trace once, including completed sessions. While streaming is enabled, selected `running` or `active` sessions refresh automatically at a 2000 ms cadence through REST as a recovery plane in connected, reconnecting, and fallback modes. Tree revision changes may request an earlier refresh through the same coalesced scheduler; they must not create an independent request loop. SSE remains the immediate push path. `stalled`, `completed`, missing nodes, no selection, pause, and unmount stop periodic trace requests. A running-to-completed transition may perform one final revision-triggered refresh; it must not restart periodic polling. Resume reconciles the current selection.
2. New turns, in-place content/reasoning/tool updates, all existing token fields, failed-tool counts, and anomalies remain visible without manual reload. An unchanged session timestamp or message count must not suppress actual changed content. Unchanged snapshots retain the existing trace state reference.
3. Only responses for the current selection and lifecycle generation may update its trace, loading state, or error. A REST response begun before an accepted SSE update cannot overwrite that newer push. Overlapping refresh triggers coalesce to at most one trace request in flight for the current selection, with at most one pending follow-up. Selection change, close, pause, and unmount invalidate obsolete results. Failed refresh preserves the last valid same-session trace and surfaces an error; successful tree polling must not conceal an outstanding trace error. A new selection must not display the previous session's trace.
4. Stable session/message identity preserves open reasoning state, message order, failure-detail expansion, copy controls, and reading position. Preserve the existing latest-first/oldest-first behavior and jump-to-latest controls. Trace refresh must not remount existing message items or force-scroll an operator who is reading away from the latest edge. Updates within an existing message must preserve the visible reading anchor as well as additions of new messages. Keep current initial reasoning defaults.
5. Existing SSE event names and trace/tree JSON shapes remain compatible. SSE subscribers stay nonblocking, streamed trace payloads are flushed, and cancellation unregisters the subscriber. Do not introduce a persisted trace revision or ledger schema change.
6. Read-only SQLite change detection gates reconstruction. A stable-connection `PRAGMA data_version` observation can supply an opaque source generation; connection replacement or an unknown generation invalidates cached snapshots. Reuse successfully built snapshots in both tree anomaly projection and SSE trace broadcast until the database changes. In-place changes must invalidate even when session timestamps do not advance or optional message/part update columns are absent. Revision lookup or trace lookup failure is an error, not evidence that the trace is empty or unchanged. Cache installation must not associate old data with a newer source generation; concurrent mutation causes invalidation/retry on the next read. Bound refresh cache lifetime to current discovered sessions and allow a single on-demand selected trace; evict departed entries. Existing direct trace retrieval remains fresh and read-only.
7. Work bound: let N be discovered sessions, H the total visible trace bytes, S subscribers, and P the configured backend poll cadence. An unchanged tick does O(N) tree/status work and constant-size change checks, without full-history reconstruction. A source-changing tick may rebuild O(H) once across visible sessions, with subsequent tree/SSE consumers sharing the result; broadcasting changed payloads costs O(S) channel attempts per event. Each browser requests only its selected active trace at most once per 2000 ms interval, plus coalesced selection/revision/manual work. This slice does not promise per-row incremental storage or elimination of reconstruction after unrelated database writes. Full-trace snapshot memory is O(H) for discovered sessions plus one selected lookup; retain the existing bounded recent-message buffer policy separately.

## Architecture and exclusions

Go domain comparison functions receive values and perform no I/O, clocks, or mutation. They compare complete meaningful trace content, not only lengths or totals. SQLite observation, cache synchronization, source errors, lifecycle, and SSE remain in `backend/internal/adapters/live` and HTTP boundaries. TypeScript pure comparison/active-status helpers belong in `web/src/domain`; scheduling and network ownership stay in the view or a narrowly scoped view hook. No `any`, `interface{}`, or emojis. No telemetry schema migration, status-model redesign, new configuration option, alternate harness support, ordering feature, broad cache framework, or unrelated cleanup.
