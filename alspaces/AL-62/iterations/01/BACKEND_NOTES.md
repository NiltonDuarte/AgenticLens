## Diagnosis and implementation

Codex response-item native/custom calls retained neither skill loads nor delegations. Added extraction within the existing owning-thread inherited-history guard. Native spawn calls retain call/event identity and explicit child UUID where returned; task namespaces remain child_reference without guessed UUID. Native skill calls retain unknown execution outcomes. Successful literal cat reads of skill files in direct exec-command JSON or recorded exec wrappers become skill_file_read evidence with execution outcome unavailable. Shell pipelines, substitutions, redirected output, failed results and mentions are excluded. Minimal synthetic fixtures reproduce the inspected Codex 0.166.0 wire families, including typed content-block results. The live AL-55 root/four children were read only for schema evidence and remain unchanged.

Session Skills and TaskLinks are canonical. Source invocation identity is separate from metrics InvocationFact rows. Projection methods flatten known owners and retain ambiguous root history; only reliable overlapping owner/call or owner/event identities suppress transitional echoes. Skills include name in identity to retain multiple skill loads in a single source call. Source/event/message/call identifiers, outcomes, values and parent-child direction survive DTOs. Source invocation IDs are also exposed on OpenCode normalized events (v1 callID, v2 tool content ID). OpenCode v1 recorded status is retained transiently for faithful skill outcome extraction without changing established generic tool-status classification.

Migration 5-to-6 never assigns ownerless history from role, indexes, names or timestamps. Explicit owner IDs relocate, unknown/missing owners remain lossless with ownership_diagnostics. Expand-compatible v4/v5/v6 runtime reads remain; only new known writes move into sessions. Existing migration backups remain the rollback mechanism. Normal GET/read does not migrate a ledger.

Generate, backfill and capture now carry auxiliary facts in their owner snapshots. Refresh replaces only successfully recovered owner snapshots, including authoritative empty facts. Legacy ownerless history cannot be deleted by successful local extraction. Incomplete Codex parsing aborts generate rather than publishing partial facts. Non-refreshed owners receive mixed-source-age diagnostics in generated ledger. Capture/history immutable-owner serialization and AL-76 equal/unknown-checkpoint rejection remain intact.

## Limits

No source-recorded skill execution result exists for a completed file load; it must not become an execution success rate. A recorded child namespace does not establish its UUID. Arbitrary executable wrappers and shell grammars are deliberately not evaluated to infer skill loads. Source families not inspected in real local data rely on self-contained existing family fixtures; no claim of live OpenCode v1/v2 compatibility runs is made. Parent owns full make, upstream integration, review consolidation and publication.
