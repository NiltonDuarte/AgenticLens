## Source and path selection

### Confirmed verdict: S01 and generation source precedence in S02

Generation uses explicit `--source` first, then `telemetry.default_source` from the selected `.agenticlens-config.local.yaml`. If neither selects a source, fail with an actionable error and write no output. Invalid explicit source selection fails rather than falling through to configuration. Implicit OpenCode selection is removed. This confirms configured source selection for generation; backfill's source options and local-file selection remain separate boundaries. The other confirmed verdicts below settle their respective boundaries.

### Confirmed verdict: S03

Codex source-path selection uses explicit `--codex-home` where supported, otherwise `telemetry.sources.codex.home` from the selected `.agenticlens-config.local.yaml`. Automatic `$CODEX_HOME` and `~/.codex` discovery is removed. Missing, invalid or unavailable paths never trigger another location. Extraction fails with an actionable error and no output; optional dashboard hydration reports unavailable source data while preserving recorded ledger visibility. Apply this policy at production composition and adapter boundaries; do not change explicit path interpretation, which remains under S06.

### Confirmed verdict: S04

OpenCode configured-path selection uses explicit `--db-path` first, otherwise `telemetry.sources.opencode.database_path` in the selected `.agenticlens-config.local.yaml`. Shared `.agenticlens-config.yaml` `database.path` is removed as a source-path input. Missing supported source-path choices fail normal required-setting validation; retain no special removed-key handling. Other database settings remain separate. S05 settles built-in home-path discovery below.

### Confirmed verdict: S05

Remove automatic `~/.local/share/opencode/opencode.db` substitution from both default configuration and `OpenDB`. Final order: explicit `--db-path`, otherwise `telemetry.sources.opencode.database_path` in the selected `.agenticlens-config.local.yaml`, otherwise an actionable error with no extraction output. Invalid or unavailable selected paths never trigger another location. Optional dashboard hydration reports unavailable source data and preserves recorded ledger visibility. Enforce the rule at composition and adapter boundaries, including empty-path adapter calls. Explicit path interpretation remains under S06.

### Confirmed verdict: S06

Allow explicitly supplied `~/` paths and expand the prefix to the current user's home; home-resolution failure produces a clear error. Relative source paths in the selected `.agenticlens-config.local.yaml` resolve against that file's directory. Relative CLI paths resolve against the invocation directory; absolute paths remain absolute. Preserve physical symlink/`..` traversal semantics. Resolution or access failure never causes another path to be invented or searched.

### Confirmed verdict: S07

Select the workspace root from explicit `--workspaces`, otherwise `workspaces.dir` in `.agenticlens-config.yaml`. Relative CLI paths resolve from the invocation directory; relative configured roots resolve from the shared configuration file's directory. Missing, invalid or unavailable selected roots fail clearly without trying `workspaces`, `alspaces` or another location. For another project's target, use its configuration for required project policy; never borrow unrelated caller-project source settings. Preserve S06 explicit path rules.

### Confirmed verdict: S08

Creating a new configuration requires explicit nonblank `--workspaces`; the YAML generator also rejects a missing workspace root. Remove the writer's internal conventional OpenCode database-path substitution; source paths come from explicit setup choices. Missing required choices fail before writing configuration files. Completion/local-only updates preserve existing valid values. Numerical presets, output filename and release-version selection remain separate decisions.

### Confirmed verdict: S09

Retain whole-file local configuration selection for linked worktrees: first use `.agenticlens-config.local.yaml` beside the target checkout's shared configuration; only when that local file is absent, select the base checkout's local file using the same repository's Git worktree metadata. A present invalid or unreadable worktree-local file fails without trying the base. Missing or unusable selected base policy fails with its exact path and setup guidance when local policy is required. Never merge keys, copy files or write base settings automatically. Relative configured source paths belong to the selected file's directory under S06. Guided setup remains base-only; no per-worktree file is required when a usable base file is selected.

This replaces the proposed removal of base-local selection. It is a deliberate configuration-file selection policy for frequent worktree creation, not permission to invent source values, discover home stores or use an unrelated project's configuration. The revised order is confirmed.

### Confirmed verdict: S10

Shared-only reads of persisted ledgers remain available when local sources or capture policy are unnecessary. Optional hydration reports unavailable source data without hiding recorded ledgers. Generation and other operations requiring capture state use the S09-selected local file with explicit `telemetry.capture.enabled` and `telemetry.capture.state_dir`; do not inherit shared capture policy or invent missing values. Invalid or missing required policy fails before publication with the exact setting/file and base-checkout setup guidance. Declining capture does not install its integration or automatically uninstall an existing one. Preserve S09 base-only guided setup, without per-worktree copying or writes from linked worktrees. No new local keys are introduced. Numerical capture defaults remain a separate decision.

The existing setup skill already describes much of this guidance; reconcile actual init/writer/runtime behavior with that canonical flow. This combined proposal replaces the earlier separate S10 runtime and guidance proposals. The complete merged S10 verdict is confirmed; it does not authorize installation in the current repository.

## Identity and session discovery

### Confirmed verdict: I01

Remove hardcoded `AL`/`GEN`/`PO` substitutions from backend normalization and frontend prefix lists, including when cleanup leaves no usable prefixes. Required `ticket.prefixes` comes explicitly from `.agenticlens-config.yaml`; missing/invalid required configuration errors clearly. Without configured or legitimately observed prefix values, the UI shows an empty state rather than invented options. Preserve recorded ticket IDs. Legacy/custom parsing rules remain separate decisions; no new local key is introduced.

### Confirmed verdict: I02/I03 literal prefixes

Configured prefixes are literal strings after surrounding whitespace cleanup. Leading/trailing `-` or `_` are valid and must not be rejected or stripped; no separator is globally mandatory and no separator is automatically appended. Prefix filters match independently rather than assigning every ticket exclusively to its longest matching prefix. Preserve recorded ticket spelling and leading zeros; do not collapse distinct IDs by removing/inserting separators.

Required examples: filtering by `T` includes `T01`, `T02`, `T-01`, `T-02`, `T_01` and `T_02`. Filtering by `T-` includes only the two `T-` examples, and `T_` only the two `T_` examples. `_TEAM` is a valid configured prefix. These forms are supported configured-prefix behavior, not a silent legacy fallback. The broader suffix/custom-pattern and ordering rules remain separately scoped; no additional separator restrictions are inferred from these examples.

For this repository, explicitly configure `AL-`, `AL2-`, `GEN-`, `MGT-`, `PO-` and `FIX-`, preserving descriptions and ticket-type mappings. This changes prefix configuration, not existing ticket IDs or workspace names. Apply consistent literal matching across normalization, filtering, API/UI consumers and type inference. This confirmed verdict supersedes rejection of edge separators, mandatory-hyphen normalization and exclusive longest-prefix filtering.

### Confirmed verdict: I04

Within a recognized prefix, sort ticket numbers naturally. Equal numeric values retain distinct spelling and use the full recorded ID as a deterministic text tie-breaker (`T-01` before `T-1` ascending). IDs unmatched by configured grammar remain visible, ordered as recorded text after recognized IDs in ascending order without invented prefixes. Use the same character ordering in Go/TypeScript. Descending reverses comparisons correctly; complete ties retain input order. Filtering and stored IDs remain unchanged.

### Confirmed verdict: I05a/I05b

I05a removes `ticket.custom_patterns` from runtime models, loader/writer, generation templates, active documentation and this repository's shared configuration. Literal configured prefixes cover the approved separator-free/hyphen/underscore forms. Custom regex currently provides arbitrary additional formats and capture-based extraction; existing tests explicitly expect `ISSUE-(\d+)` to extract only `456` from `ISSUE-456`. Removal ends that recognition/extraction path. Remove the feature without a replacement regex path, special old-key detection or migration guidance. Validate only the supported current configuration. Preserve recorded IDs and I04 visibility; do not rewrite ledgers. No project-specific nonempty custom patterns were found in the inspected runtime configuration; external adoption usage remains unknown.

I05b requires mappings only for `ticket.prefixes`: require explicit nonblank `prefix` and `description`, with optional `ticket_type`. Remove scalar decoding and validate the supported mapping schema normally, without conversion handling. Preserve literal prefixes, descriptions and supplied type mappings; do not invent metadata. Setup/init must collect missing required descriptions and emit mappings. Both verdicts are confirmed and supersede the earlier proposed retention of regexes and scalar prefix entries. No new local configuration keys are involved.

### Confirmed verdict: I06a/I06b

Direct OpenCode lookup uses supplied `--session-id`/`--nonce` only, without automatic ticket-title or workspace-content discovery. Ticket identity alone cannot select a source session. Missing, invalid or unmatched required selectors fail with actionable guidance and no extraction output. Preserve existing exact capture bindings; explicit backfill recovery remains under I07.

For both OpenCode v1/v2, an explicit session ID must identify an existing root exactly. Search nonce text literally, with SQL wildcard characters treated as ordinary characters; group matching records by root and require exactly one root. If both selectors are supplied they must resolve to the same root. Conflicts, no matches and ambiguity fail without newest-session tie-breaking, alternate strategies or output. This supersedes automatic fallback and the former nonce-first precedence when both selectors are supplied. Remove the obsolete --allow-empty escape hatch; legitimate selected roots with complete zero-invocation snapshots remain valid.

### Confirmed verdict: I07

Retain `--allow-fallbacks` solely as explicit backfill opt-in. Without it, use exact stored owners only. With it, permit clearly reported heuristic discovery from title/configured workspace evidence, using configured roots and literal matching. Never overwrite known owners, replace another harness, hide incomplete exact recovery or select among ambiguous roots. `--force` never enables discovery. Direct generation retains confirmed I06 rules. Unknown/unavailable recorded history remains preserved; heuristic enrichment does not certify complete exact recovery.
