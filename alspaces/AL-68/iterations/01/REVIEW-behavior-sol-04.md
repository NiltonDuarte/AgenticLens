## Behavior traced and consequential hypotheses

On successive completed calls each class reaches first priority with the full configured byte and session allowance; the remaining classes share leftovers. This applies to allowances above one as well as the one-attempt case. Each class retains its own parent/owner continuation, so full-budget turns also advance within that class. This directly refutes both previous always-first monopolization paths without discarding failures or increasing limits.

Ordinary refresh uses the same exact-source read, failed-read charging and snapshot acceptance operation. Its per-pass attempted-owner set prevents a second refresh from reading the same owner twice. A later second refresh can use remaining capacity for newly discovered children. Budget exhaustion preserves accepted snapshots and marks work pending. The native byte replay visibly alternates pending/current outcomes while retaining input 30 after acceptance; pending on a later exhausted pass does not roll facts back or falsely advance refreshed_at.

Those items also keep child_discovery_pending true. OpenCode discovery still uses native parent queries and source-ID pages, independently of title or ambient repository context.
