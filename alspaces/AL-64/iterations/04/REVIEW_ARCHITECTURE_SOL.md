## Consequential hypotheses and disposition

- **Evidence could be reconstructed from grouped scalars or drift to a different invocation. Refuted for inspected production paths.** Codex `finalizeFacts` captures native turn identity/start into each model accumulator and writes the one-based row beside the corresponding invocation. OpenCode v1/v2 capture native assistant-message timing before producing each model row. `SessionsFromFacts` preserves invocation order and multiplicity; generation policy projection changes optional collections without filtering or sorting invocation rows. `CombineTranscriptsWithPolicy` retains per-owner evidence, and generation replaces whole owner snapshots. The selector keys source/session/row and checks model and exact cutoff; ambiguous rows cannot establish exact advice.
- **Capture or retained history could masquerade as fresh native proof. Refuted.** Capture `sourceRead` is request-local; only successful exact source reads populate its evidence. `ReconcileResult.SourceEvents` and checkpoint evidence have JSON exclusion tags and never enter the registration snapshot. `MergeSourceEvents` replaces evidence at the same complete-owner boundary as source events. Explicit extraction takes precedence over capture for both facts and evidence. Cross-harness ID collisions are rejected by the existing `ValidateSessionMerge` boundary before generation merges facts. Stored owner snapshots and retained DTOs contain no native checkpoint evidence, so their eligible subtotal selects F04. `classifyGenerationBaseline` and `retainUnrefreshedGenerationOwners` continue to preserve portable accepted facts without receipts/source corroboration.
- **The functional core could acquire I/O, clocks, stateful deduplication or publication responsibility. Refuted.** `checkpoint.go` imports only sort/time and uses supplied values; no current-clock lookup, adapter dependency, external action or mutable global was introduced. It returns typed cases and renderer parameters without modifying the supplied facts/evidence. The CLI owns escaping, exact message rendering and writer errors. Request-local maps handle row ambiguity and interval duplicates; there is no durable checkpoint state or scheduling mechanism. The additional OpenCode entry points preserve existing callers while passing optional transient evidence to the real extractors; they do not create a new source-selection policy.
- **Subtotal arithmetic or caller uncertainty could restore the removed aggregation message. Refuted.** Exact interval age is evaluated independently of rounded invocation totals, with division avoiding configured-threshold multiplication overflow. Complete, known-short intervals finish without F04; incomplete/missing attribution can still select qualified F04. SourceOpen is checked after known-short suppression. Source-open historical qualification is separate from numeric duration. Existing numeric accumulators, `DurationInterval`, `MeasuredDuration`, token/cost logic and optional metric projection are unchanged by this diff.
- **Configuration expansion could reset metrics, change local precedence or expose new API metadata. Refuted.** `decodeGenerationConfig` initializes independent existing metric defaults and feedback180, strictly validates the new shared mapping/int64 value and retains existing unknown-setting rejection. Domain defaults, YAML writer and default template are aligned; bootstrap scaffold omission uses loader defaults. `Load` retains its explicit local allowlist and does not add generation overrides. `ConfigHandler` still constructs the sanitized `ProjectConfigDTO`, whose fields exclude generation. Ledger/invocation/session persistence DTOs and HTTP projection DTOs have no new checkpoint or reason fields. Frontend source/schema are unchanged.
- **Optional advice could precede publication or certify unsupported runtime behavior. Refuted.** `runGenerate` calls the selector/writer after the existing requested ledger/summary output, journal commit and diagnostic acknowledgement. Publication failure exits before feedback; writer failure remains nonfatal. Automatic capture generation bypasses feedback. The production caller argument is explicitly empty, so extraction roots, environment, nonce and receipt do not promote F01/F02/F05. Those cases remain gated selector/renderer support. The native capability report distinguishes source-open Codex observation and installed declarations from an unverified executing-caller/next-turn handoff; its acknowledged limits agree with the code.
