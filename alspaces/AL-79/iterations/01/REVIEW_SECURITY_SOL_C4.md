## Correction assessment

- **SEC-01, original severity 5: corrected at source/formatter boundary.** `capture/hooks.go:90-105` selects PowerShell formatting on Windows, invokes the quoted native path with `&` and doubles apostrophes within literal arguments. `projectBindingArgument` uses the same platform-appropriate quoting. The user-level receive branch still uses the selected native directly. Host-independent tests exercise the actual formatter with spaces, apostrophes and literal shell-looking session/request values. `test_windows_distribution.py:test_rendered_native_user_binding_command_executes_in_powershell` obtains feedback through native dispatch, executes the emitted command with explicit ticket substitutions and its rendered repo argument, then checks exact binding. This is the correct behavioral oracle, but it was not executed on this Linux host. The prior precise counterexample (a bare quoted Windows executable interpreted as a string) no longer applies.
- **Common PowerShell command transport and advisory bound:** both installed-dispatcher and bootstrap branches call `Invoke-NativeTransport`, with `UseShellExecute=false`, explicit Windows CRT argument encoding, and inherited standard handles. Empty values, embedded quotes and trailing backslashes are encoded rather than passed through PowerShell's native argument conversion. The timeout path limits the advisory wait to 1500 ms, invokes absolute SystemRoot taskkill with `/T /F`, bounds cleanup, and attempts final direct-process termination. The setup copy is byte-identical. Existing Windows tests exercise both routes with exact arguments/streams and the final child's liveness, but remain unexecuted locally. This is static correction verification, not Windows process proof.
- **Incompatible native admission and stable worker retention:** `InstallUserCodex` first retains and validates a private snapshot before creating the install root or user home. `RetainExecutable` checks regular executable input, copied size/inode/timestamps, reread digest and final metadata; it validates format, capture protocol, dispatch protocol and build identity on the copied executable. Incomplete/changed bytes cannot become the accepted replacement. Existing retained destinations must be regular files with the expected digest. The immutable digest path continues into worker children, avoiding mutable preferred-output substitution. Targeted incompatible-admission and mutation regressions passed in this run.
- **Resource leases and recovery:** `user_install.go:167-195` re-reads root/home pending resources and the current legacy resource receipt after acquiring leases; an unheld resource causes a retry before recovery writes. After rollback, migration is recomputed and every actual planned legacy target is checked against held leases at lines 204-217. `acquireInstallLock` is a nonblocking real kernel lease, so conflicting resources fail instead of waiting in a cross-root acquisition cycle. The new actual-second-installer resource-race test passed in this run; prior durable-prefix/interrupted-migration controls are reused from C4 TEST_EVIDENCE.md.
- **Legacy migration and unknown executable callbacks:** `legacyUserChanges` removes only exact receipt-attested groups and checks all remaining groups before returning a mutation plan (`user_migration.go:49-77`). `legacyCaptureGroupsRemain` recognizes brands and parsed command-handler `capture receive`/`dispatch codex-hook` token sequences, including an otherwise unbranded executable invocation. C4's actual installer regression verifies the changed-statusMessage duplicate in both base/worktree migration, then clean migration after explicit removal of that unknown callback; its passing result is reused from DISTRIBUTION_EVIDENCE.md.
