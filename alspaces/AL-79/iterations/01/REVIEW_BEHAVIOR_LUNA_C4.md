## Correction hypotheses and evidence

1. **Legacy callbacks could remain active beside user hooks after installation or explicit migration.** C4’s `legacyCaptureGroupsRemain` checks actual hook groups for branded AgenticLens callbacks and `capture receive` / `dispatch codex-hook` command invocations. `checkLegacyUserConflicts` applies this to discovered original-checkout hooks and refuses activation when such groups remain. For an explicit migration, `legacyUserChanges` removes only receipt-attested unchanged groups, then rejects leftover branded/actual receive callbacks before preparing the transaction. That path preserves unknown or modified callback bytes and does not treat the migration flag itself as ownership proof. The post-recovery planning order is relevant: resource discovery and recovery precede the fresh strict migration plan, so an interrupted transaction does not validate a stale pre-recovery view. Existing C4 POSIX migration oracle and focused Go results are consistent with these guards; native Windows execution remains unverified.
2. **A disabled legacy or migrated installation could keep publishing new source facts through an already-running worker.** `automaticCaptureEnabled` resolves current selected-local policy on each pass and returns false for disabled policy before source collection. `captureWorkerFence.current` also checks current enablement before allowing handoff; `WorkerSuccessor` repeats the policy check before launching a successor. The allowed boundary is explicit: a publication already committing may finish within the bounded pass timeout, and disable retains already accepted facts. Reused C3 evidence for `TestCaptureLiveDisableStopsWritesAndManualRecoverySurvives` states that the publisher was live before disable, then a source mutation occurred before idle expiry; later writes/renewals stopped while manual recovery and accepted facts remained. C4 does not alter this path.
3. **Exact child binding or another ticket’s publication could be broadened to the parent or overwrite its ledger.** Binding and reconciliation are keyed by exact source/store/session identity. `capture bind` rejects conflicting existing ticket ownership, while the worker enumerates only ticket IDs from registered rows and invokes automatic generation per exact ticket. Reused worker-shaped C4 test evidence publishes parent `TEST-100` and explicitly bound child `TEST-200` separately: child keeps source-proven `ParentID=root` and its own input facts, while parent ledger bytes remain unchanged. This supports ticket isolation without requiring the external parent’s facts to be imported.
4. **Fresh external-parent analysis could claim complete group coverage or an unqualified clean result; cached summaries could be discarded or mislabeled absent.** `completeAnomalySourceCoverage` returns false when a referenced parent is outside the ticket owner set. Source refresh therefore cannot replace ticket-level anomaly summaries as though that parent/group were fully observed. `PersistSourceAnomalySummaries` and `RetainUnrecordedCategories` preserve recorded empty/warning arrays when source is unavailable or fails to establish a replacement. The formatter explicitly discloses partial parent/group context; it keeps recorded warnings visible and avoids both a clean-session claim and wording that cached summaries are wholly unrecorded. Inspected C4 controls cover fresh, cached-empty, cached-warning and unavailable-source cases. The parent ID and owner metrics remain intact; no cross-ticket parent metrics or synthetic parent stub are introduced.
