# Reported cost and availability

AgenticLens schema v7 retains the cost evidence introduced in v5 and distinguishes reported zero from unavailable USD cost. Costs are reported amounts, not verified invoice spend. API-equivalent estimates, rate cards and subscription allocation are not included.

Invocation facts contain `cost_usd` and `cost_evidence`. Evidence has `state` (`observed`, `partial`, or `unavailable`) and nullable `known_subtotal_usd`. Observed cost has matching numeric amount and subtotal, including zero. Partial cost has a null complete amount and a numeric known subtotal. Unavailable cost has null amounts. Partial invocation evidence occurs when OpenCode coalesces source records with both reported and missing costs into one model row. New Codex extraction reports unavailable cost because rollout usage does not establish USD cost.

Valid historical numeric values are observed, including historical Codex zero. Missing/null legacy values remain unavailable. These explicit migration mappings require no source lookup or additional historical state. A successful explicit source refresh replaces only the recovered owner's snapshot using current source evidence; unavailable trees retain their persisted baseline.

Derived cost fields are nullable complete amounts, paired with `cost_summary`. A summary contains `state` (`empty`, `complete`, `partial`, or `unavailable`), nullable `known_subtotal_usd`, and `fully_observed`, `partial`, `unavailable` and `total` invocation counts. State counts sum to total. A complete amount exists only for a nonempty selection of fully observed facts. Known subtotals include reported contributions of partial facts and are displayed with explicit coverage. Invocation coverage is not financial coverage. The schema 7 lean delegation contract retires auxiliary task costs; they never contributed to invocation totals. Explicit migration drops that retired payload while preserving invocation financial evidence.

Fleet `total_cost_usd` follows the same rule. `role_costs` and `model_costs` contain nullable amounts with matching `role_cost_summaries` and `model_cost_summaries`. Time buckets expose `cost_summary` and `cumulative_cost_summary`; cumulative complete cost remains unavailable after an unknown contribution. Cost-derived shares require complete nonzero denominators. Otherwise `role_effort_unavailable_reason` explains why a distribution is unavailable. Unrelated non-cost metrics stay usable.

Runtime ingestion and new persistence require schema v7. Older inputs are accepted only by explicit migration through the existing framework. Use the migration command's dry-run, ticket filter and backup options; consult the built CLI help for exact options. v4-to-v5 conversion preserves numeric amounts and does not create a source-recovery requirement solely for missing costs. v5-to-v6 makes skill/delegation occurrences session-owned and deliberately deletes ownerless legacy rows with reported counts. See [session-owned occurrences](OWNED_OCCURRENCES.md) for the migration boundary. Pre-v4 shape migrations retain their existing source-recovery requirements.

Old binaries reject v7 files. Preserve migration backups when rollback is needed. JSON consumers must handle nullable costs and evidence/summary metadata. The bundled frontend updates with the backend. Ordinary GET requests do not migrate or rewrite ledgers.

Typed boundary DTOs declare nullable amounts, evidence and summaries explicitly. Standard JSON encoding retains the established relative order of their fields, including nested objects, with cost evidence beside the related amount. Version-specific decoders handle legacy presence and validation without rewriting an arbitrary JSON tree.

Cost KPI cards separate the short amount from availability and coverage details. Partial values are visibly labeled known subtotals; unavailable/empty values use a dash and a clear state. Comparison Average Spend uses complete-cost tickets within the active filters, includes observed zero, and states the eligible ticket count. Partial/unavailable tickets remain in other comparison metrics and rows; they are excluded only from this average and its denominator. Invocation coverage counts retain their existing meaning.

Financial validation follows explicit API/schema locations; dynamic role/model map keys are opaque identifiers. Persisted fact DTOs, compact computed exports and richer HTTP responses remain distinct contracts. Fact-ledger ingestion keeps its required reverse conversions; computed exports are verified as emitted output rather than treated as a second ingestion format. Internal numeric compatibility and per-ledger scalar rounding remain separate from precise cost summaries.
