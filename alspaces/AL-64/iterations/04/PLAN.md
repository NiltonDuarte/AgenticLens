## Approved threshold and configuration

Implement one optional setting, generation.feedback.provisional_threshold_seconds, with default 180 when absent, zero disabling only these diagnostics, and positive integer seconds overriding the threshold. Negative, fractional, null, quoted and unrepresentable values reject as invalid configuration through normal config validation. No separate enable flag, reasoning switch, anomaly rule or UI control is needed. This approval covers loader/writer/template/default semantics; the pre-implementation loader rejects this new key. Follow existing configuration ownership and precedence when placing it; this proposal establishes no new shared/local override policy or CLI override mechanism. Preserve generation.metrics keys and their defaults. Do not reuse stall_threshold_seconds or live.active_threshold_seconds: those measure different behavior.

Use unrounded native interval age at the operation's explicit cutoff for exact-interval threshold eligibility: age >= threshold, so 179999ms does not qualify and 180000ms does. A future start, invalid boundary, completed/idle/superseded interval or unsupported historical reconstruction is not current open-interval proof. Preserve all existing source-specific cutoff and terminal rules. Display exact native age as whole elapsed seconds rounded down; do not reuse invocation rounding for the predicate.

Where no exact interval can be established, a valid invocation's recorded provisional_seconds >= threshold may trigger only qualified subtotal feedback F04. The stored value is an invocation subtotal rounded by the existing producer, not a verified single-turn age. When all contributing intervals are individually known and every interval is below the threshold, emit no feedback even if their combined invocation subtotal reaches the threshold. Caller uncertainty alone must not redirect that known-short case to F04. A session/model/ticket total formed by adding individually subthreshold invocation rows does not trigger feedback. Never pool owners or models to create an apparent long turn.

Choose the strongest applicable case independently for each eligible invocation: F01 for an exact verified current-caller interval, F02 for an exact source-open interval owned by a verified different caller, F03 for an exact source-open interval with unknown caller, F04 when exact/current-source evidence is unavailable. Apply the known-short-interval suppression before selecting a case; F04 is not a substitute for removed aggregation-only feedback. If the caller is known but its current native interval cannot be matched, use F04, including for that caller's own owner row. For F02/F03, source-open is deliberately weaker than proving the process is still executing. Missing proof does not invalidate the provisional estimate accepted in iteration 03.

## Exact feedback templates and cases

Placeholders: {source} is the ledger's recorded harness; {session_id}, {role}, {model} and {invocation_row} identify the actual owning session/invocation, with row a transient one-based position within that session, not a newly persisted ID. {provisional_seconds} is that invocation's recorded subtotal. {threshold_seconds} is the effective threshold. {interval_kind} is the native source's truthful interval label, such as turn or assistant message; {interval_id}, {started_at} and {elapsed_seconds} come only from the corresponding native interval. {caller_source}/{caller_session_id} identify an independently verified caller. {harness} names the protocol whose continuation capability was assessed. Render source values as escaped single-line text so IDs/models cannot inject extra diagnostic lines. Unknown role/model labels remain unknown; do not invent identities or substitute the root.

Every line is an stderr human diagnostic. No line enters JSON stdout, ledger JSON, summary Markdown, API, frontend, capture registry or a persisted dedup record. Static prose and punctuation below are exact proposed copy; only placeholders vary.

F01 — trustworthy caller identity matches the owning source/session, independently verified native context identifies the caller's current open interval and its start, and that interval's exact age is at least the threshold. Native protocol capability for these claims must be verified for the installed harness/version. If this proof is unavailable, do not emit this variant.

> AgenticLens checkpoint: source={source}; session={session_id}; invocation={invocation_row}; role={role}; model={model}; recorded provisional subtotal={provisional_seconds}s. Your verified current {interval_kind} {interval_id}, started at {started_at}, has reached {elapsed_seconds}s (threshold {threshold_seconds}s). At a natural task boundary, complete this turn normally, then refresh telemetry in the next turn. Generating again in this same turn does not close the interval.

F02 — caller identity is trustworthy and differs from the owning source/session; fresh native evidence identifies a threshold-crossing open interval for this owner. This may be a root, child, sibling or another recorded owner. Do not tell the caller to complete someone else's turn.

> AgenticLens checkpoint: source={source}; session={session_id}; invocation={invocation_row}; role={role}; model={model}; recorded provisional subtotal={provisional_seconds}s. Source reports open {interval_kind} {interval_id}, started at {started_at}, at {elapsed_seconds}s (threshold {threshold_seconds}s). This belongs to another session; verified caller={caller_source}/{caller_session_id}. Let that owner reach a natural completion boundary, then refresh its source. Do not force another agent to complete for telemetry.

F03 — an exact source-open interval reaches the threshold but the invoking caller is not trustworthy or unavailable. Ledger owner identity remains available; caller uncertainty is not owner uncertainty.

> AgenticLens checkpoint: source={source}; session={session_id}; invocation={invocation_row}; role={role}; model={model}; recorded provisional subtotal={provisional_seconds}s. Source reports open {interval_kind} {interval_id}, started at {started_at}, at {elapsed_seconds}s (threshold {threshold_seconds}s). The invoking caller is unverified; this interval may belong to another agent. Refresh after the owning session completes naturally; no current-caller rollover is established.

F04 — the owning invocation's recorded provisional subtotal reaches the threshold, but native interval identity/start, trustworthy matching current-interval context or usable current source evidence is missing, partial, unsupported or retained-only. Owner identity comes from the accepted ledger. This single variant covers caller-known and caller-unknown cases without claiming either a single long interval or a current process.

> AgenticLens checkpoint: source={source}; session={session_id}; invocation={invocation_row}; role={role}; model={model}; recorded provisional subtotal={provisional_seconds}s (threshold {threshold_seconds}s). This subtotal may cover multiple open intervals or retained observations. Current native interval evidence is unavailable or unverified; no single long turn or current-caller rollover is established. Preserve these recorded facts and refresh when the owning source is available.

F05 — append once per command after F01 when native next-turn continuation is unsupported or has not been independently verified. This is the complete fallback notice, including the case where there is no automatic way to initiate a later turn.

> AgenticLens checkpoint: automatic next-turn continuation is unsupported or unverified for {harness}. This command will not end the turn, schedule another turn or resume itself. After normal turn completion, a user or supported harness action must start the next turn before telemetry is refreshed.

There is no automatic-continuation success message in this slice. If a native continuation API exists, document and verify it independently; adding scheduling/execution requires a separately approved implementation boundary. Even supported scheduling would not permit invented completion markers or same-turn refresh described as final. These messages do not request stopping unfinished task work merely because time passed.

No-feedback cases: disabled threshold, zero/absent provisional with no eligible exact native interval, individual age/subtotal below threshold, completed interval, several individually known subthreshold intervals crossing only within an invocation subtotal, and aggregate-only crossings across invocation/model/session/owner rows. Do not add an all-clear or completed-coverage message. A rounded subtotal of 180s with a proven sole native interval aged 179999ms remains below the exact interval threshold; it must not produce F01/F02/F03 or be misclassified as missing-proof F04. Existing generation warnings/errors continue independently.

## Concurrent feedback and repetition

Do not stop at the first eligible owner or suppress child feedback when the root qualifies. Evaluate all invocation rows in the resulting ledger, retaining source freshness distinctions per owner. Emit exact-interval variants F01/F02/F03 once per qualifying native interval. Emit subtotal variant F04 at most once per applicable invocation, including F04 for unresolved interval attribution alongside an exact-interval message when necessary. Each message retains deterministic interval identity/start where known and explicitly labels the invocation subtotal. Never add those repeated displayed subtotals together. When any eligible interval in that invocation is the verified current caller interval, use F01 only for that interval; other qualifying intervals in the same caller session without current-interval proof receive F04 once as qualified invocation-level feedback, not another current-turn instruction. Its displayed number remains the full recorded invocation subtotal; do not present it as a separately measured remaining amount. Do not claim the whole invocation subtotal is the current interval's age.

Sort base feedback by recorded source, exact session ID, role, model and invocation row, then native start and ID where present. Retain duplicate legitimate invocation rows by row identity. Do not deduplicate owners across tickets or reassign attribution. Emit F05 once at the end if applicable. For example, one current caller, two active children and one retained owner can yield F01, F02, F02 and F04, followed by F05; if caller identity is unknown, fresh interval owners yield F03 instead. Known intervals that are all shorter than the threshold produce no message, including within one invocation; do not route them to F04. Cases are classified per invocation/interval evidence, not once for the entire command.

Old retained evidence may emit F04 again on explicit generate commands; it never causes repeated automatic rollovers. There is no persisted feedback state, automatic polling or retry. A repeated explicit command can repeat a diagnostic truthfully. A later complete source snapshot replaces the owner normally; native completion removes/replaces its provisional contribution. A same-turn generation may advance a supported provisional estimate but cannot manufacture completion. Natural completion followed by next-turn refresh is the suggested checkpoint sequence, not a promise that duration, tokens, USD or further children are globally final.
