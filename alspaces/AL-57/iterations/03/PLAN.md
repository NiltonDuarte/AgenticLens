## Grounding

- adapters/cost_json.go currently recursively recognizes invocations/tasks by tokens/model/role/subagent_type and summaries by cost_* field names. It handles output nulls, summary fallback, fleet maps, unavailable distribution maps, legacy evidence inference and validation in one byte transformer.
- adapters/ordered_cost_json.go carries object member lists and RawMessage maps to compensate for serializer reordering. Typed serializers already provide the needed struct order without this general object framework.
- adapters/schemas.go already has InvocationFactDTO conversion and a custom typed invocation wire struct, but its internal float64, costAbsent flag, shared domain task structs and ledger-level MarshalJSON methods still depend on the generic normalization. AgenticMetricsLedgerDTO also retains numeric domain rollups rather than fully typed cost projections.
- adapters/http/dto.go WriteJSON marshals a closed set of concrete response families, then calls NormalizeCostJSON on every response, even unrelated events/build/config/live responses. WorkspaceDetailResponse embeds domain.AgenticMetricsLedger; workspace lists, fleet, comparison and progression also emit domain values directly.
- adapters/repository.go SaveFactLedger marshals the fact DTO; SaveMetricsLedger marshals SerializeLedger, rewrites its JSON, then indents again. Both must serialize the final typed representation once.
- domain/migration/engine.go decodeLedger calls decodeCostPresence before decoding domain/legacy structs. That preprocessing recursively edits bytes and converts partial null amounts to internal subtotals; it must become version-selected typed decoding and explicit domain assembly.
- domain/cost.go already owns pure amount/evidence/summary semantics. Shared amount/evidence validation may live here without importing adapters into the domain migration package.

## Concrete design and work sequence

1. Establish a small pure validation function in domain/cost.go for nullable amount plus optional evidence under a required-evidence policy. Proposed shared interface: ValidateCostEvidence accepts amount *float64, evidence *CostEvidence, required bool, and returns error. It enforces existing finite/nonnegative and observed/partial/unavailable combinations, returning contextual errors to callers. Missing-required-key checks stay in the known schema decoder because nullable pointers alone do not distinguish omission from null. Keep source/JSON I/O outside this helper. Do not alter accepted legacy or summary semantics.
2. Make the actual invocation and task boundary structs carry nullable *float64 cost_usd and typed evidence. Replace hidden scalar-default inference with explicit conversion functions. Domain-to-wire conversion uses EffectiveCost and summary.CompleteAmount, keeping a partial subtotal in evidence while the complete amount stays null. Wire-to-domain conversion restores the internal accumulator only from validated observed amount or partial known subtotal. Task presence must be retained independently of its numeric value, including explicitly present zero.
3. Introduce concrete version-specific fact decode structs in adapters for the known canonical v4 and v5 session/task locations. Probe schema_version once, dispatch to the appropriate decoder, validate the full owning schema, then convert explicitly to domain. Legacy v4 missing/null means unavailable; valid numeric means observed. v5 requires the existing wire members/evidence combinations. A small json.RawMessage field or explicit presence flag at known cost_usd/cost_evidence locations can distinguish missing required fields from allowed null; it must not traverse unknown objects or select their types by coincidental field names. Preserve strict unknown-field/trailing-JSON handling, current structural validation and retired-field compatibility.
4. Provide typed output DTOs/converters for GroupedMetric, RoleMetric, ModelMetric, WorkflowEfficiency, thread model/role/tree metrics, AgenticMetricsLedger, FleetSummary, TicketComparisonRow and TimeBucketMetric. Preserve complete amount and cost_summary field names and declaration order; use *float64 in cost_usd/total_cost_usd/cumulative_cost_usd, map values *float64 for fleet costs and unavailable distribution percentages, with existing companion summaries/reasons. Cumulative summary remains separate from bucket summary. Preserve effective-summary fallback for older in-memory numeric callers at conversion time, rather than interpreting serialized JSON. Reuse a converter for identical shapes; do not build a generic serializer framework.
5. Keep distinct concrete metrics export and HTTP ledger DTOs where their existing shapes differ: the CLI export's established fields must not gain HTTP facts/threads, and the HTTP payload must retain those fields and their order. Change WorkspaceDetailResponse.Ledger to its HTTP projection. WriteWorkspacesResponse, WriteFleetResponse, WriteComparisonResponse and WriteProgressionResponse convert their known input types before WriteJSON. Restrict ResponsePayload to the resulting concrete wire families. Events, errors, config, build, live session/trace/anomaly responses remain explicitly typed pass-through values because they do not carry the affected cost projection. Enumerate the entire union and its writers when checking no response family was omitted.
6. Wire SerializeLedger and AgenticFactLedgerDTOFromDomain directly to typed nested DTOs. Remove ledger MarshalJSON wrappers whose only purpose is recursive rewriting; retain a narrowly typed custom codec only where actual field-presence or representation needs it. SaveFactLedger, SaveMetricsLedger, migration runner writes, backfill writes and CLI output must marshal/indent their final DTO once with existing indentation/newline/order. Search every NormalizeCostJSON/NormalizeLegacyCostJSON/validateWireCostFields call and replace it at its actual owning boundary; delete the generic APIs and ordered helper after their last callers disappear.
7. Replace migration/cost_decode.go with concrete schema decode types, preferably named by version family/responsibility. Probe version in engine.go then decode known canonical sessions/task links or legacy root invocations/task links using nullable cost fields. Convert those typed collections into domain.SessionFact/InvocationFact/TaskLinkFact without serializing a rewritten intermediate document. Preserve flat legacy invocation id/parent/user ownership, conflicting root/session collection rejection and removed-id guards, all row occurrences, event sanitization and existing diagnostics. v1-v4 absence/null stays unavailable before any scalar defaults; v5 contradictions fail before domain conversion. Shared cost validation comes from domain/cost.go; migration must not import adapters. Retain current migration invariants and chain behavior.
8. Delete adapters/cost_json.go, adapters/ordered_cost_json.go and the obsolete recursive migration decoder after typed routes are integrated. If cost_decode.go remains as a filename, it must contain only the concrete version-selected decoder/conversion responsibility; no renamed walker is acceptable. Review production paths before expanding tests; this is a bounded boundary refactor, not an unrelated source/UI/domain arithmetic redesign.
