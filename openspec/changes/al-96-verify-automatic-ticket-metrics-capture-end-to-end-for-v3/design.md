## Decisions and ownership

- **Operator command.** Use `agentic-lens --al-offline --al-project <project> capture prepare-publication --repo <project> --ticket-id <id> --json-output <existing-directory>/agentic_metrics.json` outside the native session. It validates the exact ticket ID and directory, then records one first-write selection under `agenticlens.state_dir` for the physical project, ticket and retained destination identity. Repeating the same pending selection is idempotent. A conflicting pending selection or occupied target fails visibly. Session binding still supplies ticket ownership, title and type. Launching the configured native client supplies the lifecycle callbacks and starts the worker.
- **Writer admission.** Resolve the canonical ledger by ticket on every automatic pass. A proven absent ledger can use the private selection. If its exact destination has the matching pending transaction, admit it for recovery. Other ambiguous, incomplete or unavailable discoveries remain errors. Use the normal destination bounds, retained directory and publication ownership checks. Serialize first-publication validation and initiation for the same physical project and ticket under the same operational state, including explicit first writes. Keep the existing directory lease against simultaneous writes to the same target. A protected Codex publisher uses its admitted `agenticlens.state_dir`, the existing private path checks for the selection and journal, and the verified directory identity at publication. State inside workspace or granted writable roots fails existing protected state admission. Neither a worker argument nor a binding response carries path authority.
- **Retry and finalization.** Tie the private selection to the exact first publication transaction. If the process stops before the complete set is durable, recover the previous set and retry the same selection. Once the artifact set is durable, persist the consumed selection linked to the transaction before finalizing its public pending indicator. If interrupted in that window, finish the same committed transaction under the lease. The consumed selection remains unavailable after acknowledgement, even when the ledger later disappears from the same physical directory. Normal refresh uses the resolved ledger path, including after a move. The selection adds no ledger fields or public workspace files.

## Steering

The AL-96 conversation established that the worker owns first ledger creation and directed that manual `generate` be avoided. This supersedes using manual first publication as the setup bridge for this work. The gate starts at an empty selected destination and records binding, first commit and completion refresh as separate observations. Existing ledger reads, explicit manual recovery for other work and established source ownership remain available.

The OpenCode 1.19.5 development package `v3.0.0-rc.0+al96.dev1` measured 15.068 seconds from native completion to commit with a 15-second refresh interval. The completion callback records a durable request, but the running worker sleeps for the whole interval and applies the same wait after success. Make new eligible generations wake an idle worker after its configured debounce. Keep periodic source scans, failure backoff, bounded lifetime and generation acknowledgement semantics. Verify the timing again on the corrected package and cover the wake with an interval long enough to distinguish it from the periodic refresh.

The Codex 0.170.0 development package `v3.0.0-rc.0+al96.dev2` published the root and two direct children, while the native rollout also proved a nested child for the implementing session. That session's delegation emitted no nested capture callback. Use successful native spawn outputs as bounded discovery hints for bound parents, then verify the actual child owner, parent and project in native metadata before inheritance. Limit the scan to native rollout stores and retain existing continuation and source budgets. Rerun the gate with an exact native grandchild on both Codex and OpenCode.

Independent review identified recovery ordering and continuation failures. Sync the private consumption record before making a recovered transaction publicly complete. Recover an exact owned transaction before requiring complete discovery for a fresh write, so two interrupted tickets can each recover. An unambiguous current ledger takes precedence over any prior selection. At the retained original directory, a closed selection can recover an ordinary pending refresh only when the owned journal holds a valid prior ledger of the exact ticket. This leaves the selection closed to initial creation. Keep the worker active while bounded Codex child discovery advances. Completed sweeps stay closed until fresh native evidence warrants another scan. The native gate checks that the displayed ticket duration matches the source-backed rollup and associates its held and completed observations with their publication diagnostics. One OpenCode run recorded SQLite contention and took 26.624 seconds to settle. Allow a bounded retry for this registry contention while retaining normal backoff for persistent or unrelated failures.
