## Blocking finding

### ARCH03-1 / CAP-12 remaining — P2: discovery can permanently consume refresh's byte allowance

Locations: `backend/internal/adapters/capture/reconcile.go:80` through `:89`; `backend/internal/adapters/capture/children.go:72` through `:76`.

The correction reserves session attempts for ordinary owner refresh, but passes the entire byte allowance to child recovery first. For every allowance above one session, recovery always runs first; the persisted phase only changes scheduling when `sessionBudget == 1`. A retained malformed metadata file that fits the byte allowance can therefore reserve all bytes on every pass. The remaining session attempt reaches `extractExact` with zero bytes and cannot refresh a valid owner, even when that owner's complete source fits comfortably within the requested total budget. Rotating queue and owner cursors cannot repair this with one queued path and one bound owner.

Reproduced through a freshly built native candidate binary `/tmp/al68-arch03-cli`, using `/tmp/al68-arch03-budget.py` and isolated fixture `/tmp/al68-arch03-budget-mxv0ypl9`:

1. Register/bind Codex `root` to TEST-100 and accept its original source snapshot, input 10.
2. Receive SubagentStop for one malformed 1,024-byte metadata file. Its unresolved queue evidence is retained, as required.
3. Append an actual later timestamped source record to root. Its complete source is now 509 bytes and yields cumulative input 30.
4. Run eight separate `capture reconcile --ticket-id TEST-100 --max-sessions 2 --max-source-bytes 1024` passes. Every pass reserves 1,024 bytes, makes two attempts, leaves root pending with input 10, and preserves the exact original `refreshed_at`. Neither the source nor queue changes between passes.
5. Control: change only the session allowance to one. The alternating refresh turn reads 509 bytes and accepts input 30. This proves the source fits the original byte budget and is valid; the two-session schedule caused the failure.

This is a supported bounded continuation setting, not an oversized owner that requires a higher limit. The pending diagnostic says to increase the allowance or continue reconciliation, but continuing cannot make progress. Required correction: give owner refresh fair access to source bytes across repeated passes, including access sufficient to read an owner that fits the total allowance. Preserve failed-read accounting, unresolved queue evidence and source-parent proof. A regression should hold the byte allowance constant, keep an unresolved child ahead of a valid growing root, and require eventual root refresh with both counters bounded. This is the remaining CAP-12 scheduling defect, not a request for broader architecture changes.
