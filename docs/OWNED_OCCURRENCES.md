# Session-owned skill and delegation occurrences

Schema 6 stores `skills` and `task_links` only inside their owning session. Runtime ingestion, HTTP responses and new persistence accept schema 6 only. Root collections and `unresolved_facts` are rejected rather than normalized on read. A rejected individual workspace reports the migration requirement without hiding valid sibling workspaces. Ordinary GET never migrates or rewrites a ledger.

Use explicit `agentic-lens migrate --target-version 6` for older files. The writer publishes only the current target; older transitions remain internal steps of the migration engine. Inspect `migrate --help` for ticket filtering, dry-run and backup options. The sequential migration retains earlier cost transformations, then moves legacy rows only when their explicit native session identity identifies a known owner. Ownerless rows are deliberately deleted. The migration reports separate dropped skill/task counts in its audit notes; it does not guess ownership from a root, role, model, time or local index. Keep backups for rollback: older binaries cannot ingest schema 6, and deleted historical rows cannot be reconstructed from the migrated ledger. No bulk migration is implied by installing a new binary.

Each occurrence retains available native message/item/event/call/turn provenance. Diagnostic `source_ref` identifies a source location and is not a native invocation identity. Metrics invocation rows coalesce role/model measurements and are never used as invented raw occurrence owners. Repeated calls remain separate occurrences. Session-local positions do not identify facts across sessions.

OpenCode v1 and v2 tool events produce session-owned skill/task calls with native source identities and recorded outcomes. Codex selected-skill user requests and structured attachments produce activation requests with unknown outcomes; one direct selection immediately followed by its matching attachment is one request with both evidence references retained. Unrelated user content closes that bounded envelope; repeated standalone attachments remain separate occurrences. Opaque native tool outputs retain unknown outcomes. Positive native status/success fields or explicit failure evidence are required for a known outcome; a returned task namespace alone is not success. Catalogues, quoted instructions, inherited history and ordinary shell reads do not establish activation.

Codex native `spawn_agent` calls produce delegations independently of child discovery. Outputs pair by exact call ID. Explicit output `session_id` remains available even when the child is unavailable. Raw opaque `agent_id` is retained separately as `child_agent_id`; it is never assumed to be a session UUID. When output contains only a task namespace, `child_reference` retains it. A unique child with the same native parent ID and source-provided `agent_path` resolves the child session in read projections without requiring live source access. Namespace-derived UUIDs are never written back as native source facts. A raw agent identifier resolves only when actual native child metadata proves that exact session identity and parent. No matching child remains unavailable. Multiple matching namespaces without an explicit UUID, or contradictory native parent/UUID evidence, produce a separate `child_link_diagnostic`; the original IDs, reference and execution outcome remain intact and navigation is withheld. Roles, timestamps and ordering never establish this join. A child record alone never creates a delegation call.

Skill outcome is `unknown`, `succeeded` or `failed`. The existing `success` boolean remains a recorded scalar; the explicit outcome is authoritative. Current runtime never derives an outcome from that boolean; only explicit legacy migration translates its historical recorded value. Unknown requests count as recorded activity but are excluded from known success/failure denominators. No known outcomes means the success rate is unavailable. Aggregations and session filters flatten owned arrays; there are no root compatibility stores or projections.

Successful complete local snapshots replace only their exact session owners, including legitimate deletion to empty or an older restored source snapshot. Missing, partial, malformed or other-source owners preserve their previously recorded facts. Repeated/growing snapshots replace their own occurrences without accumulation. Optional hydration cannot hide persisted facts. Valid current ledgers remain portable without private registrations, original checkout CWD, or pinned Git file equality. Explicit source/ticket associations, native identity and source/destination path containment still apply. Safe metadata from actual activation/skill/delegation events proven by owned occurrence identity is persisted for offline timeline badges; arbitrary tool events and prompt/tool/error payloads remain compacted away. These saved event projections carry `events_are_partial: true`, which describes event coverage, not source-snapshot extraction completeness. They preserve cached anomaly summaries and cannot establish event-sequence anomalies such as retry streaks. Full native session event snapshots clear that marker; event-only optional hydration does not clear it without per-owner complete-read evidence. These source completeness rules apply to generate, capture and backfill; migration's intentional deletion is limited to ownerless legacy rows.
