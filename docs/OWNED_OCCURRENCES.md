# Session-owned skill and delegation occurrences

Schema 6 is the current ledger, runtime and workspace API contract. It stores `skills` and `delegations` only inside their owning session. A skill contains exactly `name`, nullable `caller_role` and nullable `invoked_at`. A delegation contains nullable `agent_type`, nullable `invoked_at`, an optional short `description` and an optional proven `child_session_id`. Required nullable members remain present when unknown. Distinct occurrences retain their order and multiplicity, including identical lean rows.

Sessions and ledger roots contain no `events`, `events_are_partial`, `agent_path`, `task_links` or replacement provenance payload. Current decoders reject retired members even when empty or false. Root auxiliary collections and `unresolved_facts` remain rejected. A rejected workspace reports its migration requirement while valid siblings remain available. GET never migrates, hydrates or rewrites a ledger on disk.

Use explicit `agentic-lens migrate --target-version 6` for older files. Schema 5 is the previous released contract. Its single 5-to-6 transition relocates reliably owned facts, drops ownerless legacy rows with separate counts, projects lean occurrences and audits retired payload removal. It maps recorded timestamp/type values, preserves owners, order, multiplicity, invocation costs, trees and anomaly summaries, and reports converted occurrences, discarded event rows and partial markers, removed rich-field presence and unresolved discarded child references. The existing 1-to-5 cost-evidence and shape transitions remain migration inputs only. Rich types exist solely at that historical input boundary. Interim ticket implementations are not additional supported schemas or migration paths. Completed migrations with no pending steps omit the `migration` member from persisted ledgers. Explicit `migrate` and `backfill` print their completed-step and loss audit with the ledger path; an explicit migration also removes already recorded completed metadata without changing the other ledger values. Pending or partial metadata remains persisted for recovery. Save console output when the audit is needed later. Use `migrate --backup` to retain an original `.bak` file and restore that file over the ledger to revert the transformation; backfill does not create backups, so retain originals in Git or another backup before running it. A dry run changes neither ledgers nor backups. Dropped payloads cannot be reconstructed from the console audit or schema 6 alone. Installing a binary does not authorize historical bulk migration.

OpenCode v1 and v2 skill/task calls and Codex native spawn/skill calls are classified from their source records before projecting lean rows. Codex direct user skill selection followed immediately by its matching structured attachment is one activation at the initial selection time; repeated independent requests remain separate. Catalogues, quoted instructions, inherited history, path mentions and ordinary shell reads do not establish activation. Parser-local identities support envelope deduplication and exact output matching, then disappear from durable occurrences. OpenCode v2 invocation time comes from the tool state creation time; OpenCode v1 uses its native part creation time. Missing native call time remains null even when a message or trace ordering time is known. Skills expose activation counts, unique names, ticket adoption and session filters; skill outcomes and success/failure rates are retired. Tool execution outcomes and financial evidence retain their independent contracts.

A delegation belongs to its parent call. An explicit native output session ID remains recorded even when the child is unavailable. An opaque agent handle or task namespace becomes a child session ID only when exact native session metadata proves the parent and child relationship. A unique exact parent/agent-path relationship already in an old ledger may prove the link during migration, before that metadata is discarded. Roles, timestamps and ordering never prove a link. Missing or contradictory proof produces no navigable invented child ID. OpenCode checks explicit child references against the selected native source table even when that child is outside the refreshed owner set. A child record alone never creates a delegation.

Successful complete source reads replace only their exact session snapshots, including complete equal, older, fewer or empty results. Missing, malformed, partial and other-source owners preserve previously recorded facts. Repeated and growing snapshots replace rather than accumulate occurrences. Valid portable ledger facts require no private registration, source fingerprint or original checkout path. Actual conflicting store/ticket associations and unsafe project/publication paths remain rejected.

Full trace events exist only in source parser outputs and transient live or `/api/workspaces/{ticket}/events` responses. The endpoint reads exact recorded owners and returns `availability: complete | partial | unavailable`, plus required/complete session IDs and diagnostics. A complete response can contain zero events after successful complete native reads. Partial responses retain supported events and identify missing coverage. Unavailable responses contain no invented ledger-event fallback. Native tool inputs, outputs and source-proven activation/child annotations remain transient; lean occurrences never generate trace rows or join by name/time.

Stored metrics, lean panels and anomaly summaries remain usable in every hydration state. Pure calculations receive explicit ephemeral events and complete-owner coverage. Incomplete events cannot establish retry sequences or replace a full recorded summary. Rework summaries require complete coverage of their parent/child group. Aggregation covers refreshed and retained owners together. Capture snapshots, history and publication records use the same lean models and cannot republish retired traces.

Unsupported old capture snapshots remain opaque in their original local registry row until successful native re-extraction replaces them. Registration metadata and bindings remain usable; a metadata-only `snapshot_needs_refresh` diagnostic excludes those cached facts from current snapshots and publication. Reads never convert rich cache payloads into lean facts. Missing or malformed native sources retain the accepted shared ledger and the original opaque cache; unrelated tickets can continue reconciling. A fresh native read is required even when the recorded source checkpoint is unchanged.

## Optional generation categories

Schema 6 uses field presence for session `skills`, `delegations` and `anomalies`, and root `anomalies`: omitted means not recorded; an explicit empty array means supported complete inspection recorded no occurrences/findings; nonempty arrays contain recorded facts. Null is invalid for these optional category collections. The source of an omission (disabled, unavailable or unsupported) is intentionally not persisted.

`generate` applies the current shared configuration using transient typed options, including its final projection after original retained-owner equality validation. No `generation_policy`, `anomaly_availability` or replacement policy/reason metadata is written. Former AL-66 marker shapes are accepted and validated only by the canonical DTO read boundary, then discarded without synthesizing arrays. Supported files are rewritten only by an explicit write to that target; ordinary GET does not migrate files. No schema bump is introduced.

Successful complete supported source refresh replaces that exact owner's category, including true empty arrays. Missing or partial sources preserve recorded facts and unrecorded absence; partial known rows remain usable. Root and parent/child group analysis requires its own complete required source coverage. Known cached group summaries survive a missing child. Ordinary reads, saves, non-source backfill and unavailable source refresh never reconstruct absent analysis from unrelated tool totals or mark it healthy. Readers show not recorded/partial without guessing why a field is missing. Ordinary tool calls/errors remain valid across all owners.

See [generation settings](SETUP_MANUAL.md#optional-metrics-during-generation) for exact keys, precedence, transient disabled explanations and source-backed restoration limits.
