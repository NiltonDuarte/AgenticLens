## One ledger discovery and location model

Add shared `workspaces.roots`, a nonempty list whose entries contain `path` and an explicit `discovery` object. That object contains exactly the two discovery settings `max_depth` and `max_directories`; no root `id` or `min_depth` is introduced. Configuration writers, setup scaffolds and templates initialize them to `max_depth: 0` and `max_directories: 300` per entry. These are values written into configuration, not runtime fallbacks. A maximum depth of zero checks only the selected directory itself for a ledger and does not enumerate its child directories. A maximum depth of one checks the root and its immediate children; larger values extend that scope. Every valid ledger within scope is eligible. Users explicitly configure greater depth for container or nested layouts. Validate a nonnegative integer maximum depth and a positive integer directory budget. Missing settings fail with setup guidance; do not treat an explicitly configured zero as absent, infer creation destinations or silently recurse.

Depth defines the selected search scope: reaching `max_depth` is normal, not an incomplete scan. Hitting `max_directories` before that selected scope is fully examined reports incomplete discovery, preserves valid results already found and explains how to narrow the root or explicitly increase the budget. Never report a budget-truncated scan as successful absence, and never silently expand its bounds. The budget counts physical directories inspected within the selected scope, including the root; a root-only scan normally examines one directory.

Use only `workspaces.roots`, including a one-entry list for a single directory. Remove scalar `workspaces.dir` and the interim top-level `workspaces.discovery` shape entirely; explicitly reject those retired fields even when supplied alongside valid roots. Users and this repository must update their configuration before using the new runtime. Do not normalize old shapes, silently migrate them or retain compatibility parsers. Remove the old runtime single-directory `--workspaces` override rather than guessing how it maps to roots and scope; its use reports the required configuration update. Setup writers produce the new explicit root entries and preserve selected new-format values. Reject empty roots, missing/blank paths, missing/invalid discovery settings and conflicting policy. Setup previews effective values, including explicit deeper scopes for container roots. Configured paths resolve relative to shared configuration; explicit ledger/output selections retain their documented path semantics.

Update CLI help, API config DTOs, frontend validation, setup/templates, tests and active documentation together. Expose only the root collection in the changed API contract, removing the old `workspaces_dir` field without an alias or dual-response shape. Update consumers rather than preserving single-directory internal wrappers solely for compatibility. Error guidance explains the new shape; it is not an old-behavior fallback.

The domain owns immutable root, ledger candidate, resolution and diagnostic types. Filesystem adapters enumerate physical directories with cycle/alias detection and union overlapping configured coverage. Reachable symlinks remain subject to explicit physical-root containment; a symlink is not permission to traverse an unselected physical tree. Discover workspaces by `agentic_metrics.json`, read canonical ticket identity from valid ledgers and report malformed/unsupported ledgers as per-location diagnostics. A directory without a ledger has no AgenticLens workspace identity or listing, even if it contains OpenSpec metadata, planning artifacts or a ticket-like name. Root/scan limits and errors identify the configured path, actual location, issue and recovery context; no separate root identifier is needed. Siblings remain available when one root fails. Reads never create roots or identity metadata.

Use canonical ticket identity already recorded in a valid ledger. No workspace identity marker, UUID, identity sidecar, persistent directory-binding configuration, automatic creation routing or workspace bind/create/resolve commands are introduced. Folder names are labels; no naming policy is needed to discover or resolve a ledger. Recorded ticket IDs in the current supported ledger format remain authoritative regardless of folder spelling or OpenSpec creation naming conventions; no folder-name compatibility parser is involved. OpenSpec's selected ticket-prefix convention is a repository workflow choice, not an AgenticLens discovery requirement.

Resolution returns `resolved`, `not_found`, `ambiguous`, `identity_conflict` or `unavailable`, a selected physical location when available, candidate locations and partial diagnostics. One unique valid ledger resolves by recorded canonical ticket identity before and after moves. Distinct matching ledgers never merge or win by root order. Existing read/generation interfaces accept explicit location selection where needed and check recorded identity and containment; no standalone resolution command or registration step is needed. A stale explicit destination fails/retries rather than silently selecting another duplicate. Copies with the same ticket remain usable through explicit directory selection; duplication does not invalidate supported portable ledger facts. Physical filesystem identity is used transiently for alias detection and publication safety, not persisted as a new workspace identifier. Location changes never alter exact source/session ownership.

First generation receives an explicit canonical ticket ID and output destination through the generation interface; it does not recognize, register or track the folder beforehand. Successful publication creates the ledger that makes the directory discoverable. Without an existing ledger or an explicit initial destination, generation reports destination required rather than inventing a root, naming-derived path or creation route. OpenSpec or ordinary filesystem workflows create planning folders; AgenticLens has no planning-only inventory.

Artifacts remain safe static ledger-home-relative paths. Root policy can override the shared artifact list per root so historical CONTRACT/SUMMARY and OpenSpec proposal/design/tasks remain readable through the same reader after a ledger exists. Canonical spelling comes from the ledger, or the explicitly supplied ID on first generation, never lowercase folder conversion.

## Local publication state and portable interruption detection

Place operational publication journals and locks in one writable machine-local AgenticLens state home, separate from versioned installed binaries and capture-registry storage. Select it through local `agenticlens.state_dir`; setup writes an explicit value, initially `~/.agenticlens/state`, and validates/expands it through the configured-path resolver. A local override can place it elsewhere without relocating binaries. Missing/invalid write-state configuration requires setup guidance; never silently choose a cache or repository fallback. This new writer requirement replaces the previous OS-cache publication-lock location and adjacent full publication journal; no compatibility adapter is added.

Generate, automatic publication and ledger-mutating format/backfill/migration paths share the state-home resolver and transaction protocol. A writer may initialize its configured state directory without installing/enabling capture or opening its registry. Manual source extraction remains independent of capture policy, installation and registry health (AL-81); publication now requires writable operational state only. A read-only/missing/unavailable state home must stop before public artifact changes, with explicit recovery/setup context. Read-only listing/detail/artifact paths must not resolve, create or require the state home, capture state or installed engine cache. Direct native engine execution remains supported, subject to this state requirement when it writes.

Keep a small transient pending-publication indicator beside the ledger. It records only the current transaction format and an opaque transaction reference; it contains no source sessions, backups, private state-home path or separate workspace/ticket identity. This is transaction status, not the rejected workspace identity sidecar. Actual recovery data and member backups stay private in the state home, namespaced by project/worktree and transaction. Members are authorized against the current resolved ledger directory, with ledger-directory-relative artifact paths rather than authority to recreate old absolute destinations. The indicator moves/copies with the workspace, allowing another machine/user to detect an incomplete set without accessing the original state home. Completed supported-format ledgers remain self-contained and readable without private state.

Persist the private journal and then the public pending indicator durably before changing any visible member. Clear the indicator only after the whole accepted set is durable; private journal cleanup follows. Readers inspect the adjacent indicator without consulting private state and report pending/unavailable rather than displaying an accepted mixed set. If local recovery data is unavailable, including on a copied interrupted workspace, report incomplete recovery and preserve the indicator/artifacts. Never infer success from a missing private journal, fabricate an empty accepted ledger or remove the indicator merely to make reads succeed. Recheck transaction status around reads to handle publication races.

Current `capture.AcquirePublication` creates parents and locks a hash of the mutable output path; `publication_set.go` journals absolute member paths beside the ledger. Replace those assumptions with state-home coordination and a lease on the actual resolved directory without creating missing workspace parents. Hold/open the physical directory and perform public staging/replace/fsync operations relative to it on supported Linux/macOS, with no symlink following. Serialize competing writers by project/ticket and actual directory as needed so pre/post-move publishers cannot split ownership. Revalidate recorded ledger identity and configured-root membership before accepting publication; missing/replaced destinations produce a recoverable retry. A path-only check followed by `MkdirAll` is insufficient.

Support recovery only for the new transaction format. Detect retired adjacent journals or unsupported pending formats before writes and stop with explicit recovery/upgrade instructions, preserving pending data for recovery with the matching tool. A move during publication either finishes/restores the same home or remains visibly pending; unlink, replacement or cross-filesystem copying must not recreate the former parent or write to an unrelated replacement. Test real movement, private-journal/public-indicator ordering, crashes between member updates and cleanup, missing recovery state on a second machine fixture, recovery on the originating state home and unchanged repeat idempotence.
