### T-SOL-1: Git-derived naming oracle accepts a randomized substitute

- Severity: 3/10. Classification: suggestion concerning newly added coverage; nonblocking. No corresponding defect exists in the reviewed production implementation.
- Location: `backend/internal/adapters/capture/shared_state_test.go:353`, TestCoordinationTokensConcurrentFirstOpenAndStableReopen.
- Trigger/hypothesis: preferredCoordinateToken stops incorporating the administrative identifier and its qualified identity, and returns `wt-` plus a fresh random token instead. Allocation still persists that token, so same-scope reopen and cross-scope uniqueness remain correct.
- Expected/consequence: available linked-worktree administrative identifiers must be preferred and qualified. The test only checks the `wt-` prefix, so it would miss losing this naming contract while continuing to protect concurrency and isolation.

The overlay and mutated source are outside the shared checkout.
- Refuting guard/limit: production `coordination.go:117` onward actually reads observed ownership, sanitizes the administrative basename and qualifies it with a SHA-256 digest of canonical GitDirectory and GitIdentity. The mutation demonstrates an oracle gap, not a shipped bug. The fixture genuinely includes matching administrative basenames from separate repositories.
