## Hypotheses investigated

- **Grouped facts could fabricate or misattribute native intervals.** Refuted for inspected paths. Codex records native turn IDs/starts before model grouping and carries the resulting ephemeral evidence on the matching source/session/model/invocation row. Missing native IDs mark evidence incomplete rather than synthesizing an ID. OpenCode v1/v2 preserve native assistant-message IDs and starts, with the truthful `assistant message` label. Evidence is keyed back to source/session/row and checked against model and the same cutoff in the selector. Duplicate/conflicting evidence fails closed to qualified output.
- **Refresh or retained history could be mistaken for current source-open proof.** Refuted for inspected paths. `MergeSourceEvents` replaces all evidence for complete owner snapshots, including empty snapshots, while retaining untouched owners only; retained facts without fresh transient evidence produce qualified F04 when otherwise eligible. Codex historical rollout state and OpenCode terminal/superseding/cutoff rules separate known historical duration evidence from `SourceOpen`. Incomplete lifecycle evidence is marked incomplete and does not promote an interval into stronger advice. Known individually short intervals are evaluated before fallback, so a complete set of short intervals does not produce F04 merely because its invocation subtotal crosses the threshold.
- **Config parsing could silently default malformed values or change precedence.** Refuted for examined config path. The optional setting defaults to 180, accepts zero and positive representable integers, and validates node kind/tag before decoding, rejecting null, quoted/fractional/negative/unrepresentable values. The setting follows existing project configuration flow and the writer emits it; no new local override or CLI precedence path is introduced. `ValidateConfig` also rejects negative programmatic values.
- **Feedback could escape before successful publication or alter persisted output.** Refuted by `runGenerate`: feedback selection/rendering occurs after summary and JSON publication/acknowledgement paths; auto capture is excluded; stderr write errors are reported as optional and do not reverse publication. The selector evidence is transient (`json:"-"`), and the inspected code introduces no ledger/API/frontend output field or durable deduplication state. This review did not run an end-to-end standalone binary check.
- **Production could claim unsupported caller or continuation facts.** Refuted for current runtime wiring. The generic generate caller is explicitly empty/unverified, so native source-open intervals can select F03 and qualified subtotal/evidence cases F04; F01/F02/F05 require supplied verified caller/current interval/continuation evidence and are not enabled merely by extraction root, environment, nonce, path, or receipt. This matches the approved fallback. Native caller/current interval handoff and real next-turn continuation remain unverified as documented in the runtime capability report; typed pure selector tests do not establish those runtime capabilities.
- **Existing accounting or neighboring contracts could be changed through evidence plumbing.** No change to duration arithmetic or durable metrics was found in the inspected paths. Evidence is additive and ephemeral. The implementation/test reports identify reuse of numeric-accounting, AL-66 field-presence and AL-77 overlap protections; I found no new consequence to those contracts in the architecture trace.
