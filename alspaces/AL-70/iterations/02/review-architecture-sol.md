## Findings

- **ARCH-SOL-1 — required-setting authority can disagree with decoded policy (6/10, introduced).** `backend/internal/adapters/config/policy_nodes.go:34–46` flattens arbitrary YAML keys into dot-separated setting names; `loader.go:223–225` trusts that inventory independently of `yaml.Unmarshal` into typed structs. Removing nested `ticket.case_insensitive` and adding the root key `ticket.case_insensitive: true` passes `LoadFromFile`, records presence=true, but produces effective `CaseInsensitive=false`: the struct decoder ignores that root key. Thus a malformed current setting silently supplies Go’s zero value instead of the C08m required-setting error. The same namespace collision can affect boolean generation policy and explicit zero-accepting settings. The presence inventory must come from the actual structural setting path used by decoding; no retired-key detector or compatibility layer is needed. Reproduced by `TestAL70ArchitectureDottedPresence` in the disposable Go overlay; `config-probe.log` shows error=nil/presence=true/effective=false.

- **ARCH-SOL-2 — manager Codex hook skips supported YML projects (6/10, pre-existing required-contract defect).** `backend/internal/adapters/manager/run.go:263` adds a `.agenticlens-config.yaml` basename restriction after canonical `FindConfigFile` discovery. With `.agenticlens-config.yml`, every valid callback returns `{}` before selected capture policy or engine dispatch, so an otherwise enabled project silently receives no automatic capture. C06 explicitly requires the manager, engine and setup to share both canonical suffixes. `TestAL70ArchitectureHookYML` exercises exported `manager.Run`: the YAML control reaches the missing selected-local-policy error, while identical YML input returns success/`{}\n`. Source proves the same early return for a fully configured project. Remove the redundant basename authority; retain no-project no-op behavior. This probe does not claim actual harness callback/trust certification.

- **ARCH-SOL-3 — live role projection is applied twice (5/10, introduced).** `backend/internal/adapters/live/service.go:297,330–337` produces API `node.role` by applying `RoleMappings.ResolveRole`; `web/src/components/LiveSessionTree.tsx:68` now passes that projected role to `useRolePresentation().label`, which maps again (`contexts/ProjectConfigContext.tsx:22`). Under approved mappings `builder: planner, planner: other`, a real SQLite live fixture emits agent=builder/role=planner, but the actual component renders badge text `other` (and CSS class role-planner). This disagrees with API/retrospective aggregation and C08w presentation semantics. The new component test supplies raw builder as node.role, so misses the actual producer shape. Preserve one projection owner. The Go overlay produced `live-tree.json`; SSR of the unmodified component using that JSON produced `node-role-badge role-planner">other</span>` in `render.log`.

- **ARCH-SOL-4 — Git base-local selection truncates legal physical paths (3/10, pre-existing required-contract defect).** `backend/internal/adapters/config/selection.go:48–54` splits `git worktree list --porcelain` on newlines. In a disposable real Git repository whose base checkout contains a newline, Git emits that newline inside its path; selection truncates the base and reports a nonexistent local file despite the valid same-repository base-local file. S09/S06 require retaining Git-established selection and physical path meaning. Use Git’s lossless porcelain representation rather than treating path bytes as line delimiters. `TestAL70ArchitectureQuotedBase` in the final overlay reproduces failure; its initial double-quote-only control passed, so ordinary quote characters are not claimed affected.
