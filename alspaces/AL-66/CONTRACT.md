# AL-66: Optional generation metrics contract

Approved baseline, iteration 01, with the user-directed delegations naming correction. Source: the AL-66 specification under `alspaces/plan/to-do/`, requested through the agentic-lens-dev skill. Grounded revision: `a84adbe5be46c2ef52ede0987a417562715d38e1`. User scope approval recorded in iteration 01; implementation uses delegations throughout the public configuration and policy metadata.

## Configuration and command scope

Introduce three independent project configuration booleans: `generation.metrics.skills`, `generation.metrics.delegations`, and `generation.metrics.anomalies`. All default to true. An omitted section or omitted member preserves the enabled default; an explicit false survives merging. Values must be actual booleans: null, quoted strings, numbers, sequences and mappings are invalid. Errors identify the configuration path and expected boolean before modifying the requested ledger or summary.

Use the existing configuration discovery order in `config.FindConfigFile`: search upward within the project boundary, selecting `.agenticlens-config.yaml`, then `.agenticlens-config.yml`, then `.agenticlens-config.json` at each directory. The selected shared project file overlays domain defaults per member. Files are alternatives, not merged layers. The existing `.agenticlens-config.local.yaml` override whitelist remains limited to its existing machine-local source, installation and capture settings; it does not override generation metrics. There are no environment overrides or CLI overrides for these three settings. Document this exact precedence in `docs/SETUP_MANUAL.md` and generated configuration comments.

The settings govern `generate`, including its automatic/registered-source generation path. They do not rewrite other ledgers, change live collection, redact transcripts, disable tools or child discovery, change backfill defaults, or introduce a dashboard settings UI. They are an output policy rather than a global source redaction guarantee. Source parsers may still consume source records needed to establish session identity, execution totals and parent-child relationships.

## Typed policy and ownership

Model a concrete domain generation policy with independent booleans, explicit enabled defaults, and a pure, nonmutating projection over facts. Resolve configuration once in the imperative composition layer and carry the effective policy through each generation path: OpenCode schema v1, OpenCode schema v2, Codex and registered capture reconciliation. Keep default source APIs usable by live, backfill and hydration without silently applying project generation settings to those commands.

AL-62 ownership is already implemented as current schema 6, further specified in `docs/OWNED_OCCURRENCES.md`. Skills and delegations are session-owned `skills` and `delegations`. The user-facing setting is `generation.metrics.delegations`; no task_links configuration alias is introduced. It must not resurrect retired root `task_links`, root skill collections, events or rich occurrence fields. There are currently no canonical invocation-owned skill/delegation collections; audit invocation, session, root and compatibility projections for leaks rather than inventing an owner.

Disabling skills removes skill occurrences and skill-specific derived values. Disabling delegations removes delegation occurrences and delegation-specific derived values. Child sessions, parent IDs, native source labels, ordinary invocation rows, tool calls/errors, tokens, costs, duration, code facts and legitimate row multiplicity remain intact. Raw text and unrelated evidence mentioning these category names are preserved.

Disabling anomalies bypasses anomaly analysis for generation and omits persisted root/session anomalies and anomaly-derived counts, breakdowns and health claims. Generated sections and requested diagnostics must not report healthy, no anomalies or zero errors as a substitute for disabled analysis. Ordinary tool execution/error totals and independently measured numeric context usage remain available. In generated Markdown, suppress health classification labels when anomaly analysis is disabled while retaining underlying independent numeric measurements.

## Durable output and compatibility

Apply intentional omission to the complete emitted ledger, including freshly extracted owners, unavailable same-source owners, other-source owners, capture fallbacks and retained raw DTOs. A final serialization projection must prevent a retained-history writer or anomaly preparation from restoring suppressed facts after earlier filtering. Validate original ownership and retained-history equality before the intentional output transform; do not weaken collision, identity or portable-history validation to permit filtering.

Disabled category fields must be absent, never null, empty arrays or zero placeholders presented as measurements. Preserve existing enabled/default output and availability semantics, including genuine recorded-empty values where the current contract represents them. Unsupported or unavailable enabled evidence must not become successful zero measurements.

Add optional typed `generation_policy` metadata to the ledger with explicit `skills`, `delegations` and `anomalies` booleans when a generation policy needs to explain intentional omission. Its absence means no recorded policy, preserving supported existing schema 6 ledgers. This is additive schema 6 evolution; no schema version bump or implicit historical migration is planned. Update strict boundary decoding and API projections together. The metadata contains settings only, never suppressed metrics. Preserve policy presence through save/load and read projections so disabled omission can be distinguished from missing evidence or a genuine empty measurement.

Read compatibility honors the recorded omission of that particular ledger; it does not apply current project toggles as a global dashboard filter. In particular, `DeriveMetricsLedger` and its downstream consumers must not reconstruct anomaly analysis or claim successful zero analysis for a ledger recording disabled anomalies. Ledgers without this metadata and supported persisted facts remain readable with enrichment absent, partial or failed. Explicit source trace/live operations retain their existing independent behavior and must not silently rewrite the ledger. Backfill retains its existing defaults; any shared serialization change must avoid making a stale generation marker contradict facts written by another explicit command.

Regeneration with false deliberately removes prior facts of that category from the target only. This is the approved exception to ordinary unavailable-history retention, limited to those categories; all enabled and unrelated history survives. Regeneration after re-enabling recovers available source-backed facts only. An unavailable original source cannot reconstruct facts already omitted. Preserve current safe-write, publication journal, rollback and backup guarantees; do not introduce another persistence mechanism.

Generated Markdown reflects the same effective policy as JSON. `--append` replaces the prior managed metrics block and removes stale disabled values while preserving user prose. Minimal disabled-setting explanation is permitted. `--anomalies` remains a display request; while disabled it reports that anomaly analysis is disabled and cannot enable either computation or persistence.

## Architecture and acceptance

Domain policy/defaulting/projection and calculations remain pure, value-based and independent of I/O, network and clocks. Configuration decoding, source traversal, serialization, file replacement and Markdown output remain adapters/composition responsibilities. Go and TypeScript stay strictly typed, without any/interface{} or emojis. Frontend changes are limited to accepting optional policy metadata and communicating omitted data honestly in existing readers and views.

Acceptance requires actual saved JSON field-absence assertions and actual managed-summary replacement using meaningful nonempty self-contained fixtures. Cover omitted defaults, each false independently, all false, mixed settings, invalid types before output modification, first creation, existing retained owners across sources, repeated unchanged generation and off/on recovery with available and unavailable originals. Preserve raw execution evidence and ordinary invocation metrics. Select missing cases within existing config/domain/persistence/CLI/API/frontend test owners rather than duplicating their coverage. Preserve original AL-55 evidence and unrelated ticket history.

Before publication, require focused checks, independent behavior/data/architecture/test reviews under both configured model profiles, integrated `make`, existing frontend compatibility checks, and canonical frontend build plus embedded-asset and standalone-binary verification if frontend changes are made. The parent owns consolidated review, telemetry, commits and PR delivery. Telemetry is generated only at finalization, using the actual Codex source and a literal nonce; unavailable evidence remains explicitly incomplete.
