## Gaps and owners

1. **Archive and creation routes diverge.** The generated archive skill instructs agents to synchronize by hand/agent and finish with `mkdir -p` and `mv` (step 5). That route bypasses the pinned archive command's validation, delta processing and result. The generated propose skill calls bare `new change` on a free-form name, bypassing the repository helper's literal-prefix and collision checks. The workflow guide already requires the wrapper. Make the repository-specific routing explicit at the development entry point and in the setup bundle so regenerating shared skills does not restore the ambiguity. Preserve deliberate pre-archive sync as a distinct operation. The pinned top-level help exposes no standalone sync command.
2. **The central development skill links the workflow but leaves the planning/apply handoff implicit.** Its plan, approve and implement sections describe people and files. The workflow guide shows creation/status and validation/archive but omits the per-artifact and apply command loop. Add the short sequence above to the guide and link the relevant stages from the skill. Keep authoring Markdown and checking tasks with the agents. The CLI provides no command that writes the technical decision or approves scope.
3. **Ad hoc intent and tests need explicit coverage.** The project proposal rule and development schema say to link an existing roadmap ticket, while AGENTS.md permits ad hoc work. Qualify the rule for existing tickets. The durable workflow test archives the planning schema. GEN-27 exercised the development graph and delta sync separately. The Makefile does not invoke the workflow test. The workflow/setup owners can decide where pinned CLI coverage should run.
