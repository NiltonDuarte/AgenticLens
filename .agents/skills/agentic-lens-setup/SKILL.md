# AgenticLens setup

Install exact published native binaries and the setup/operator bundle in an adopting repository. The application is a standalone Go binary; Codex capture needs no Python or Node runtime. OpenCode's existing plugin remains a separate integration until its global-runtime delivery.

## Read and preserve before setup

Read the selected release help and existing shared/local YAML, inspect Git metadata and installed user hooks, and preserve user changes. Never infer required settings from AgenticLens's own repository or ticket names. Explain the concrete proposed file changes and obtain explicit user confirmation before applying adopting-repository setup or editing agent guidelines. Existing explicit authorization for those changes satisfies this gate.

Shared `.agenticlens-config.yaml` owns project/ticket/workspace/metrics rules, mandatory exact `agenticlens.version` and optional `agenticlens.binary_dir`. The native dispatcher selects host output `binary_dir/agentic-lens-GOOS-GOARCH[.exe]` when valid; absent output uses the exact installed cache. Present invalid output errors. Normal execution never downloads, selects latest or changes pins. The explicit installer alone downloads verified published artifacts; local builds need no publication.

Select the whole worktree `.agenticlens-config.local.yaml` when present, otherwise the whole base-local file found through Git. Never merge keys across local files or use base shared YAML for a worktree missing its own shared YAML. Selected local configuration owns explicit `telemetry.capture.enabled`, state, cadence/limits and telemetry source locations. Relative local paths belong to the selected file directory. Invalid or incomplete required choices error without repair/fallback. Disabled capture validates configuration, then performs no capture-only source/state I/O; manual generation remains available.

## Base and worktree boundaries

Worktree-local configuration is user-managed. Do not guide its creation/copying, create it or write base configuration from a linked worktree. Enabled configured worktrees adopt on their first real event; no per-worktree install/enrollment/manifest is needed. Discovery/status stay read-only. Perform base-local setup only from the base checkout.

For base setup retain valid existing values, show retained choices and ask only for missing required choices. Recommend capture enabled; save the explicit answer. Ask for source, its actual source path and state location when missing. Noninteractive setup requires explicit values. Use `init --local-only --capture-enabled true --source codex --codex-home <ACTUAL_HOME> --state-dir <STATE>` to fill missing base-local choices without replacing valid ones. For OpenCode use `--source opencode --db-path <ACTUAL_DATABASE>` instead. Invalid existing values need an explicit correction, not replacement with defaults.

For new shared configuration, use `init --project-name <NAME> --src-folders <ROOTS> --ticket-prefixes <PREFIXES> --agenticlens-version <EXACT_VERSION>` plus the explicit local choices above. An existing valid shared file is retained. `--complete-scaffold` completes only the unchanged installer-owned scaffold. Do not use force to repair absent worktree files.

## Explicit installation and migration

Use bundled `scripts/download.sh` or `scripts/download.ps1` with an exact published version, project and explicit destinations. Preserve edited/unowned wrappers and binaries. The installer stages the verified cache artifact and invokes native `capture install-dispatcher` for one transaction over dispatcher bytes, digest and the canonical install-root `dispatcher-installation.json`. The install-root lock and recovery journal serialize projects and effective Codex homes. Per-home hook receipts own groups; their recorded dispatcher hash is historical and cannot veto another home's valid machine update. The installer then activates the launcher pointer. Shell/PowerShell glue delegates project/development selection to native dispatch when installed; invocation never provisions binaries. Preserve other cache versions.

For Codex preview `capture install-user --repo <PROJECT> --dry-run`, review the effective Codex user home's hooks and native dispatcher, then apply the approved command. It owns only additive unchanged groups and machine-wide installation metadata. Callbacks contain no project/source/state path. Existing unknown/modified home callbacks, including Python workarounds, are preserved and diagnosed. Installation also checks current and Git-resolved original-base project callbacks; an active legacy callback requires explicit safe migration before global activation. Explicit `--migrate-legacy-repo <ORIGINAL_CHECKOUT>` removes only unchanged groups attested by the old project receipt, preserving state and unrelated hooks. Do not claim duplicate removal without native discovery evidence. Interrupted user installation keeps a recovery journal; subsequent installation acquires every affected current/prior home and legacy resource lease before restoring unchanged transaction-owned bytes, then recomputes the migration plan. Later user edits remain conflicts.

`capture uninstall-user` removes unchanged user groups and retains collection state, the installed dispatcher and its machine ownership record. Stop automatic capture through selected local `telemetry.capture.enabled: false`; uninstalling a hook is separate from deleting retained records. The legacy project installer remains for the existing OpenCode integration. Optional Git advisory hooks remain separately opt-in through `install-check`/`uninstall-check`; never alter CI/global Git settings or arbitrary hooks.

Missing/ambiguous context stays unassigned and asks for information; incidental tickets/branches/roles are not ownership. Unassigned source facts remain local. Deleted destinations are not recreated or redirected; all complete/incomplete state remains until explicit cleanup. A running worker and its subprocesses keep retained immutable executable bytes through normal exit; new invocations use the preferred valid build. Status distinguishes active/preferred build, selected configuration origin and pending/failed/disabled states.

Use `capture status`, `diagnostics` and actual native inspection to separate installation from observed capture.
