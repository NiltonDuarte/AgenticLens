## Findings

- **B-SOL-01, severity 6/10 — Windows OpenCode invokes the native manager as a PowerShell script.** The changed installer selects and validates the native manager at `backend/internal/adapters/capture/install.go:272`, then renders it into `__WRAPPER__` at line 419. On Windows the default path is `agentic-lens.exe`. The unchanged consumer in `backend/internal/adapters/capture/plugin.ts:88` still constructs `powershell.exe -NoLogo -NoProfile -NonInteractive -File <manager.exe> ...`. PowerShell's script-file option cannot execute this native binary. Every plugin receive, request and bind operation uses this function, so this breaks preserved Windows OpenCode integration. An isolated TypeScript transpilation/VM probe executed the production `call()` with a Windows platform value and recorded that exact invocation; its POSIX control selected the manager directly. This is command-construction evidence, not Windows runtime certification. Route the native executable directly and retain bounded process-tree cleanup. Probe: `/tmp/al79-behavior-sol-plugin-probe.cjs`.

- **B-SOL-02, severity 5/10 — The manager rejects inspection of a deleted worktree's retained registry.** `backend/internal/adapters/manager/run.go:136` applies live project resolution and filesystem identity checks to every capture command with `--repo`. However, `capture inspect-state` expressly accepts the recorded physical worktree even after deletion (`backend/cmd/agentic-lens/capture_relocate.go:45`) and performs no configuration fallback. In an isolated fixture with a real current registry, deleting its project and selecting the installed engine through a surviving configured project produced: direct engine `capture inspect-state --repo DELETED --state-dir REGISTRY --project-name Fixture`, exit 0 with retained observations; manager `--al-project SURVIVOR` plus identical arguments, exit 1 with `lstat DELETED: no such file or directory`. Neither recreated the destination. The generic guard newly makes this supported recovery/inspection operation unavailable through the installed command. Exempt the explicit retained-state operation from live repository comparison while preserving ordinary cross-project protection. Probe: `/tmp/al79-behavior-sol-retained-probe.py`.

- **B-SOL-03, severity 3/10 — Existing version aliases fail outside a configured project.** `backend/internal/adapters/manager/run.go:189` permits standalone companion selection for `version` but omits `--version`, `-version` and `-v`, all supported by the engine's main entrypoint. With a real manager and exact companion engine explicitly installed into an isolated HOME, outside any project, each alias returned exit 1 and “shared project YAML missing”; `version --short` and `--help` returned exit 0. Extend standalone classification to the existing aliases. Probe: `/tmp/al79-behavior-sol-alias-probe.py`.
