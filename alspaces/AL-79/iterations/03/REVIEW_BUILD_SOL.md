## Blocking finding

**6/10 — self-update silently targets the default installation instead of the invoked custom installation.** `backend/internal/adapters/manager/install.go:43–46` resolves omitted `--dest` through `config.UserManagerPath()`, which always constructs the default home path. A manager installed using the supported bootstrap `--dest CUSTOM_DIRECTORY` therefore does not update itself with the documented `self-update --version EXACT` command. Its absolute-path hook consumers and PATH entry retain the old build; a second installation is created or another owned default manager is updated instead. This violates preservation of custom destinations and the advertised independent manager update behavior.

Reproduced with real compiled managers in `/tmp/al79-build-review-gq6_roa4`: bootstrap installed manager/engine v9.7.3 under custom destination/cache paths containing spaces. Invoking `custom bin/agentic-lens self-update --version v9.7.4 --local-bin manager-v9.7.4 --sha256 VERIFIED_DIGEST` exited 0 and printed installation at isolated `home/.local/bin/agentic-lens`. The custom manager still reported v9.7.3; the new default manager reported v9.7.4. No real HOME was used. Explicit `--dest` avoids this bug, but normal documented updates must preserve the current installation. Add an actual custom-installed invocation regression asserting its identity changes and no default installation appears; existing native admission tests supply explicit `--dest`, so they miss this path.
