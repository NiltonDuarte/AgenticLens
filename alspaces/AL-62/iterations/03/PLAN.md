## Exact canonical occurrence contract

The enclosing session remains the sole owner. Its ID, source and parent metadata are inherited, never duplicated into a persisted occurrence. Read selectors may pair an occurrence with its containing session as a transient projection; that projection is not another persisted model. Arrays preserve source order and multiplicity. Neither name/time equality nor array position establishes a stable occurrence identity.

### skills

| Field | Presence and type | Meaning |
| --- | --- | --- |
| name | Required nonempty string | The source-selected skill name. A catalogue entry or path mention alone creates no activation. |
| caller_role | Required member, recorded nonempty string or null | Preserve the raw source role and existing explicit unknown-role handling. Use null if no recorded or otherwise known caller role exists; do not infer a persona from the skill name or invent a classification. |
| invoked_at | Required member, source timestamp string or null | Time of the source activation/request or explicit skill-tool call start. Null means the source has no invocation time. Never ingestion time, completion time, file mtime or a fabricated default. |

These three fields are the entire persisted skill shape. Remove success, outcome, evidence_kind, evidence_references, provenance, path, error, indexes, session/source duplication and native identity fields. Skill success is undefined under this contract; do not retain a replacement success flag, assume an activation succeeded or present a skill success/failure rate as unavailable-but-still-supported analytics.

For a direct invocation token plus its attachment describing one selection, emit one activation using the initial selection time. Distinct native requests or attachments remain distinct even with identical lean values. Continue excluding inherited/replayed parent history. Recognize explicit supported source envelopes; ordinary SKILL.md shell reads, catalogue listings, copied prompt text and arbitrary dollar-prefixed words are not new activation evidence. Source parsing may use native IDs and evidence transiently to establish these boundaries before projecting the lean row.

### delegations

| Field | Presence and type | Meaning |
| --- | --- | --- |
| agent_type | Required member, recorded nonempty string or null | The authoritative recorded requested agent type at the parent delegation call; replaces subagent_type. Use null when the source omits it. Do not infer the requested type from a child's persona/name or fill a default unless that requested value is explicitly recorded. |
| description | Optional string, omitted when unavailable | A short source-supplied task description or title. Do not copy the full prompt/message payload or create an unrequested prompt archive. When the source offers only a full prompt, omission is valid. |
| invoked_at | Required member, source timestamp string or null | Source parent delegation-call time; null when missing. Never ingestion, child-start or completion time. |
| child_session_id | Optional nonempty string, omitted when unproven | A known actual native child session ID, either recorded explicitly or established by exact native parent/child evidence. An opaque agent handle, task name or namespace alone is not a session ID. |

These four fields are the entire persisted delegation shape. Remove child_reference, child_agent_id, child_link_diagnostic, provenance, outcome, error, parent_turn, duration, cost/evidence, raw prompts and session/source duplication. Rename domain/DTO/selectors and user-facing concepts by responsibility, rather than retaining task_links as a compatibility alias. Actual session metrics remain the source of session cost and duration; no replacement delegation analytics store is introduced. Unknown caller role, requested agent type or invocation time never discards a supported occurrence: retain it with the corresponding required member set to null. Grounding in codex/occurrences.go confirms spawn_agent extraction copies args.AgentType, which can be absent; requiring an invented nonempty value would lose or falsify valid delegations.

A delegation belongs to the parent call, even if the child is unavailable. Child existence alone does not synthesize a delegation. Follow-up and messaging calls are not spawn calls. Resolve source handles only with exact supported native relationship evidence; never by role, name, order or temporal proximity. Ephemeral extraction/hydration metadata may retain handles, native call IDs and proof while processing a source. It must not be serialized into the canonical ledger, capture snapshots, history publications or a sidecar designed to recover the removed payload.

A proven child_session_id may survive save/reload and unavailable-owner refresh; a source-derived proven ID must not later be described as a raw ID returned by the original call. Document that distinction in extraction/migration evidence, without adding a persisted provenance field. If proof is absent or contradictory, omit the link and show navigation unavailable; transient diagnostics may explain why. A known ID can be retained while its destination is unavailable. Removal of opaque persisted references intentionally loses raw-reference auditability and means an unresolved historical link needs its original source/hydration to be resolved later. Not every previous navigation link can be promised to survive without sources. Accept this lean tradeoff; do not restore handles, hidden keys, identity sidecars or a parallel relationship cache to avoid it.

Grounding also finds that canonical SessionFact.agent_path is copied through DTOs and sessions for ResolveTaskChildren's saved opaque-reference joins. Remove it from canonical domain/DTO/current API/TypeScript shapes together with those joins; reject it in current validation. Native Codex metadata and rollout parsing may retain agent paths ephemerally for source persona handling and exact child proof. Migration input may consume old agent_path before dropping it, so uniquely proven historical child links can be preserved. Do not keep this orphaned technical field or introduce source locators elsewhere as replacement provenance.

## Events, hydration and anomalies

Canonical SessionFact, ledger DTOs, workspace ledger API responses and frontend SessionFact lose events and events_are_partial entirely. Current root fact shapes already reject retired events; retain rejection and add the partial marker to root and session rejection checks. Current writes must not emit either member, including empty events or false partial markers. Remove PersistedOccurrenceEvents and other transforms whose purpose is to retain saved occurrence events. Migration-only old-input DTOs may still decode the retired fields.

Keep separate transient TraceEvent/EventFact models, WorkspaceEventsResponse.events, live traces, tool-call details and GET /api/workspaces/{ticketId}/events. Source adapters return or retain ephemeral session-keyed events independently of canonical SessionFact; pure anomaly calculations take explicit ephemeral inputs plus relevant stored facts. Do not keep a nonserialized Events member on canonical SessionFact as an indirect transport. Domain calculations remain pure; source reads and hydration remain imperative adapters. No new disk cache, sidecar or publication payload may recreate the removed event field.

HydrateWorkspaceEvents loads the native sources for the sessions already recorded in the ledger, respecting harness, ticket/project ownership and exact native relationships. It returns a transient response; no merge into ledger facts, mutation of the input ledger, disk write or hidden persistence follows. WorkspaceEventsHandler must stop building a committed-event fallback and stop treating a nonempty response as the only successful result. Full tool-call waterfalls and live traces remain available when sources are available. No lean occurrence is expanded into an artificial trace row or matched to a source event merely by name/time.

Define a transient discriminated trace availability state shared by Go response validation and TypeScript: complete, partial or unavailable. Complete can contain zero events only after successful complete source reads. Partial means some required source/session coverage failed or is incomplete; return supported events with explicit coverage/diagnostics. Unavailable means no usable trace evidence, including missing source access. Existing hydration/source fields must be made consistent with that state; remove obsolete includes_baseline/committed-event fallback behavior where it serves only the deleted baseline. Pending/request failure are frontend request states, not a persisted fact. This availability metadata belongs only to the transient endpoint/live presentation.

Stored skills, delegations, tool/token/cost metrics and anomaly summaries remain visible before hydration and after unavailable, failed, empty or partial hydration. Hydration may enrich anomaly associations with actual events, without saving them. Keep recorded summaries when sources are absent. Compute event-dependent rules from complete source events where available, not from sparse skill/delegation rows; never invent consecutive-error streaks, retry sequences, timing or known zero anomalies from missing events. Ticket summaries and totals cover refreshed plus retained owners. Partial event input cannot overwrite a full recorded owner summary as though it were a complete re-extraction.
