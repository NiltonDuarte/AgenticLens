# AgenticLens setup

Install exact published native binaries and the setup/operator bundle in an adopting repository. The native manager handles installation/routing; a separate standalone engine handles capture, telemetry and the embedded dashboard. Neither requires Python or Node in production. OpenCode's existing plugin remains a separate integration until its global-runtime delivery.

## Read and preserve before setup

Read the selected release help and existing shared/local YAML, inspect Git metadata and installed user hooks, and preserve user changes. Never infer required settings from AgenticLens's own repository or ticket names. Explain the concrete proposed file changes and obtain explicit user confirmation before applying adopting-repository setup or editing agent guidelines. Existing explicit authorization for those changes satisfies this gate.

Shared `.agenticlens-config.yaml` or `.agenticlens-config.yml` owns project/ticket/workspace/metrics rules, mandatory exact `agenticlens.version` and optional `agenticlens.binary_dir`. Shared discovery supports either canonical suffix, fails if both are present and never bypasses invalid selected policy. The native manager selects host output `binary_dir/agentic-lens-engine-GOOS-GOARCH` when configured. Missing, blank, inaccessible or invalid selected output errors; absent binary_dir deliberately selects the exact pinned installed engine. Normal execution never downloads, selects latest or changes pins. The explicit installer alone downloads verified published artifacts; local builds need no publication.

Select the whole worktree `.agenticlens-config.local.yaml` when present, otherwise the whole base-local file found through Git. Never merge keys across local files or use base shared YAML for a worktree missing its own shared YAML. Selected local configuration owns explicit `telemetry.capture.enabled`, state, cadence/limits and telemetry source locations. Relative local paths belong to the selected file directory. Invalid or incomplete required choices error without repair/fallback. Disabled capture validates configuration, then performs no capture-only source/state I/O; manual generation remains available.

## Base and worktree boundaries

Source/capture worktree-local configuration is user-managed; do not copy it or write base capture configuration from a linked worktree. A worktree may explicitly declare its own local `agenticlens.state_dir` without enabling capture or changing base/source choices. The `init` writer, including `--local-only`, retains its base-checkout setup requirement; do not advertise a linked-worktree setup bypass. Enabled configured worktrees adopt on their first real event; no per-worktree install/enrollment/manifest is needed. Discovery/status stay read-only. Perform base-local setup only from the base checkout.

For base setup retain valid existing values, show retained choices and ask only for missing required choices. Explain manual telemetry, automatic capture and integration installation separately; obtain an explicit capture enable/disable answer. Never silently enable capture or install an integration. Ask for source, its actual source path and state location when missing. Explain every consumed numerical/boolean setting and record the approved choices, including intentional false/zero/empty containers; never seed missing values from runtime presets. Noninteractive setup requires explicit values. Use `init --local-only --local-settings <APPROVED_LOCAL.yaml> --capture-enabled <true-or-false> --source codex --codex-home <ACTUAL_HOME> --state-dir <STATE>` to fill missing base-local choices without replacing valid ones. For OpenCode use `--source opencode --db-path <ACTUAL_DATABASE>` instead. Invalid existing values need an explicit correction, not replacement with defaults.

Prepare explicit shared/local YAML candidates, review all choices and use `init --settings <SHARED.yaml> --local-settings <LOCAL.yaml> --workspace-root <ROOT> --discovery-depth 0 --directory-budget 300 --publication-state-dir <PUBLICATION_STATE> --agenticlens-version <EXACT_VERSION> --dry-run` from the base checkout. New shared setup requires explicit `workspaces.roots` in the approved candidate or repeatable nonblank `--workspace-root` choices and a canonical output basename; reject ambiguous shared suffixes before writes. Prefix mappings require supplied descriptions; require four approved production/tests include/exclude lists and an approved Git base. Explain generation metrics, manual feedback, shared summary enablement/filename, roles, live/anomaly values and consumed local capture budgets/timings using the current configuration reference. Apply only after the concrete proposal is approved. Noninteractive input must provide approved values explicitly. An existing valid shared file is retained. `--complete-scaffold` completes only the unchanged installer-owned scaffold. Do not use force to repair absent worktree files.


## Workspace and OpenSpec choices

Explain each selected root's explicit path and discovery policy. Writer initialization is maximum depth 0 and budget 300; a container holding ticket subdirectories needs an explicitly selected greater depth, commonly 1. Missing runtime fields do not acquire defaults. Retired `workspaces.dir`, top-level discovery and runtime `--workspaces` are rejected; users must update. Ledger identity comes only from recorded ticket IDs, never folder names. Before first generation provide an explicit ID/destination; no registration, identity sidecar or workspace-management CLI is added.

Publication writers use selected-local `agenticlens.state_dir`, initially `~/.agenticlens/state`, for journals/backups and locks independently of capture state. Setup writes it explicitly with `--publication-state-dir`; writes can initialize that directory without capture installation/enablement. Completed-ledger reads require no private state. Pending-publication indicators travel with moved/copied ledgers and remain incomplete when private recovery data is unavailable. Unsupported old journals require explicit recovery with the matching tool, not a compatibility converter.

OpenSpec adoption is optional platform workflow setup; this repository chooses it for selected execution work. Install the optional reviewed bundle with `scripts/install.sh --version <EXACT_RELEASE> --dest <PROJECT> --with-openspec` (or approved local `--source-dir`); this preflights conflicts and does not run npm, init or capture. Follow the [pinned workflow](../../../docs/OPENSPEC_WORKFLOW.md), review the exact published CLI/schema and existing assistant files before approved initialization, and preserve unrelated/custom guidance. Configure changes/archive as ordinary explicit roots and proposal/design/tasks/delivery artifact paths. Roadmap tickets remain separate. Schema readiness, checkboxes and archive are not implementation approval, verified delivery or automatic ticket completion. Project context/rules are advisory agent inputs, not enforced native gates. Preserve PO planning-only sessions and all specialist/approval/review/telemetry requirements from AGENTS.md. Other OpenSpec assistants do not become AgenticLens source adapters.

## Explicit installation and migration

Use bundled `scripts/download.sh` with an exact engine pin, project and explicit destination. A first remote bootstrap requires an exact manager release (`--manager-version`, defaulting to explicit `--version`); offline bootstrap accepts `--local-manager-bin`/`--manager-sha256` and `--local-bin`/`--sha256` for the separate engine. The shell only obtains/checks the bootstrap manager; shared YAML parsing, engine installation and routing live in native Go. Install the manager directly as the user's PATH command; there is no shell launcher, separate dispatcher executable or pointer file. Preserve edited/unowned files and other cache versions. Manager updates use `self-update --version <EXACT_MANAGER_VERSION>` and never change a project engine pin.

Bootstrap provisions the requested project engine. Outside configured projects, engine commands use the manager's exact-version companion from the default user cache. When the manager version differs, explicitly install that companion with `agentic-lens install <MANAGER_VERSION> --install-root <USER_HOME>/.agenticlens`; bootstrap never downloads an unpublished companion implicitly. `--manager-version`, `manager --help`, installation and self-update remain available without an engine.

For Codex preview `capture install-user --repo <PROJECT> --dry-run`, review the effective Codex user home's hooks and installed manager, then apply the approved command. It owns only additive unchanged groups and the home hook receipt; manager executable ownership remains separate. Callbacks contain no project/source/state path. Existing unknown/modified home callbacks, including Python workarounds, are preserved and diagnosed. Installation also checks current and Git-resolved original-base project callbacks; an active legacy callback requires explicit safe migration before global activation. Explicit `--migrate-legacy-repo <ORIGINAL_CHECKOUT>` removes only unchanged groups attested by the old project receipt, preserving state and unrelated hooks. Do not claim duplicate removal without native discovery evidence. Interrupted user installation keeps a recovery journal; subsequent installation acquires every affected current/prior home and legacy resource lease before restoring unchanged transaction-owned bytes, then recomputes the migration plan. Later user edits remain conflicts.

`capture uninstall-user` removes unchanged user groups and retains collection state, the installed manager and its ownership record. Stop automatic capture through selected local `telemetry.capture.enabled: false`; uninstalling a hook is separate from deleting retained records. The legacy project installer remains for the existing OpenCode integration. Optional Git advisory hooks remain separately opt-in through `install-check`/`uninstall-check`; never alter CI/global Git settings or arbitrary hooks.

## Binding, publication and verification

Hooks notify the exact-session worker. If current-task ticket context is explicit, answer its exact binding request directly without another confirmation. Missing/ambiguous context stays unassigned and asks for information; incidental tickets/branches/roles are not ownership. Unassigned source facts remain local. Source-proven same-task children inherit a bound parent unless explicitly bound already; parent callback IDs never become child IDs.

Workers publish during activity/checkpoints with bounded coalescing/retry. Failure preserves facts and pending work for a later trigger. Deleted destinations are not recreated or redirected; all complete/incomplete state remains until explicit cleanup. A running worker and its subprocesses keep retained immutable executable bytes through normal exit; new invocations use the preferred valid build. Status distinguishes active/preferred build, selected configuration origin and pending/failed/disabled states.

Use `capture status`, `diagnostics` and actual native inspection to separate installation from observed capture. Record actual Codex version/interface and hook sourcePath, normal user trust, root binding, source-proven child IDs, source collection and automatic publication. Never bypass/forge trust, manufacture callbacks or introduce per-worktree certification as production activation. Installed files and fixtures are not runtime proof; unavailable coverage remains explicitly incomplete.

Portable ledgers remain valid project history without the producing machine's private state or source. Preserve unavailable owners and other harnesses; complete local snapshots replace only their exact owners. Follow the canonical [portable ledger contract](../../../TECHNICAL_GUIDELINES.md#portable-ledger-contract), [configuration reference](../agentic-lens-operator/references/configuration.md) and [setup manual](../../../docs/SETUP_MANUAL.md). Never commit raw transcripts, request tokens or private paths as evidence.

The selected engine must expose `engine protocol` 1, `capture protocol` 3 and its own version identity. The manager exposes `manager protocol` 1 and `--manager-version`; it refuses the engine role probe. Engines never select or invoke another build. The manager preserves caller cwd and relative arguments even when `--al-project` selects configuration elsewhere. Callback execution uses validated project context.

AgenticLens supports macOS and Linux on amd64 and arm64. Windows is unsupported. Use the Bash bootstrap for maintained platforms; do not offer PowerShell installation or Windows artifacts.

Engine retention validates a complete stable snapshot, host format/platform, capture interface and build identity before use. Manager installation separately validates manager format, protocol and its own identity. A changing, truncated or incompatible replacement leaves the accepted installation intact. Retained worker children execute the admitted immutable build; normal manual POSIX dispatch replaces its process image so cancellation and signal status remain intact. The bootstrap preserves exact native argument transport, caller working directory and bounded setup diagnostics.

Legacy `capture disable`/`uninstall` stops further automatic passes for that integration while preserving accepted facts. A successfully migrated global user integration remains independent of the retained inactive legacy receipt. Local `enabled: false` remains authoritative for all automatic paths; manual generation uses project/metrics settings and authoritative source selection without capture installation, state, pass or budget policy. It never reads or modifies the capture registry or automatic ticket bindings.
