## Finding

### SEC-SOL-C2-01: Windows native binding feedback supplies an unexecutable shell command

- Severity: **5/10**. Classification: introduced reachability of an existing platform-specific command-rendering defect; required-contract correctness issue, not a demonstrated injection vulnerability.
- Locations: `backend/internal/adapters/capture/hooks.go:168` through the new user-level branch at line 170; `BindingPrompt` at line 90 and `projectBindingArgument` at line 189. Caller: `backend/cmd/agentic-lens/dispatch.go`, nativeCodexHook's `capture receive --user-level`, then `capture.go`'s ReceiveCodexUser selection.
- Supported expectation: the new native integration must supply a directly usable exact-session binding response on supported Windows, without depending on a historical wrapper. The contract's native installation, explicit binding and platform-specific launch glue requirements apply.
- Trigger and call path: an unbound Windows session receives SessionStart or UserPromptSubmit. ReceiveCodexUser selects BindingPrompt unconditionally and bypasses WrapperBindingPrompt, which contains the existing Windows-specific handling. BindingPrompt uses POSIX QuoteArgument and emits the quoted native path directly as a command.
- Concrete counterexample: with an ordinary native path `C:\Users\Alice\.agenticlens\bin\...\agentic-lens-windows-amd64.exe`, the supplied instruction starts `'C:\Users\Alice\...\agentic-lens-windows-amd64.exe' capture bind ...`. PowerShell treats the quoted path as a string expression and rejects the following command arguments; invoking a quoted executable requires the call operator `&`. cmd.exe does not interpret the supplied single quotes as executable-path quoting either. POSIX apostrophe escaping and the appended --repo argument also need platform-correct formatting.
- Consequence: following the supplied response fails before capture bind runs. The exact session remains unassigned and its ticket publication waits indefinitely unless the responding agent independently repairs the command. No attacker-controlled input is needed for this failure.
- Evidence and refutation check: the branch is new in C2's full baseline diff, and no later formatter transforms its additionalContext text. `TestNativeUserBindingUsesSelectedHandlerDespiteStaleWrapper` only checks that the prompt contains the executable, then separately invokes captureCLI with an argument vector; it does not execute the generated command. Passing that test therefore does not establish Windows command usability. The native evidence demonstrates Linux binding, where POSIX quoting is appropriate.
- Required correction: render the native binding command and appended project argument for the supported Windows shell, preserving the selected native build and exact opaque argument values. Verify the rendered command itself, including paths with spaces/apostrophes, rather than reconstructing equivalent argv in the test.
- Evidence limit: this is a precise source-level counterexample. Native Windows/PowerShell was unavailable; no Windows parser or callback execution is claimed.
