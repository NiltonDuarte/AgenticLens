# Configurable models and finding attribution

The coordinator must load [model-policy.yaml](model-policy.yaml) before dispatch. This is declarative skill-kit configuration interpreted by the coordinator; it is not a runtime scheduler or an AgenticLens dashboard feature. Keep model choice out of persona files so the same responsibility is independently reviewed under each configured model.

## Configuration and execution

Version 1 defines named profiles with provider_instance_id, exact model identifier and explicit reasoning_effort. default_profiles is the nonempty ordered list for every selected reviewer, including generic/specialist/narrow reviews. reviewer_overrides may replace that list for a named persona with another nonempty list of defined profile IDs; changing policy is explicit configuration work, never an automatic response to cost, capacity or model availability. Do not apply an override that conflicts with current user instructions. Reject unsupported versions, duplicate YAML keys/profile IDs, unknown profile references, repeated IDs in a reviewer list, missing/blank settings and empty selections. Do not silently use inherited settings or defaults when this file is missing/invalid.

Current user policy is every selected reviewer on BOTH gpt-6.1-sol/high and gpt-6-luna/medium. Thus four core focuses expand to eight independent discovery runs; specialists add two runs each. A low-risk scope exception can reduce applicable focuses, not remove one model from a selected focus. A verifier is a distinct phase; it does not satisfy a missing discovery run. When a separate reviewer is dispatched to verify findings, its configured model profiles also apply unless the user explicitly changes the policy. The parent can validate an already conclusive probe without spawning a verifier.

Expand the roster before launch as (persona, profile, phase, candidate revision). Record the resolved policy in temporary coordinator records and retain the selected model/effort beside final findings and review outcomes. Allocate a unique run ID and private scratch report path per cell, including retries. Keep full reports in private working storage during review; commit concise results rather than embedded report/log archives. Give paired discovery runs equivalent requirements/source evidence and separate fresh contexts; do not reveal their partner's findings before both first passes finish. Preserve all selected cells through capacity-limited waves; a queued/unavailable run is not a completed review.

Resolve model/effort availability from the active harness catalog. The provider_instance_id identifies an installed provider instance, not an interchangeable model family. Explicit user-selected settings must be passed to the actual dispatch tool, not merely written into the prompt. For T3 delegate_task, map profile provider_instance_id/model into target and reasoning_effort to the supported target.options.reasoningEffort key after orchestrator_capabilities; obey the host's delegation/lifecycle rules. Native dispatch, when allowed by the active host policy, uses its model/reasoning_effort fields and fresh context. Do not change providers/models, omit effort or switch dispatch mechanisms to bypass an unavailable requested configuration. Report the missing cell as INCOMPLETE and identify the unavailable setting.

Record requested settings separately from settings acknowledged by the dispatch response and, when available, observed in source-session metadata. A model name asserted in prose is not runtime proof. Keep observation/source fields null with an explanation when unavailable; do not infer usage, model identity or cost. A dispatch failure, mismatch or unacknowledged required setting leaves the cell incomplete. An acknowledged dispatch is sufficient to report the configured execution, but must not be relabeled as source-session verification. If later metadata contradicts it, reopen the cell.

## Working records owned by the coordinator

Keep full reviewer reports, dispatch responses, candidate snapshots and raw build logs in private temporary storage while review and corrections are active. Children own only their assigned reports; the parent owns shared finding/run records and consolidated conclusions. Preserve independent first passes and historical failures until reconciliation is complete. Raw transcripts and secrets never belong in Git.

Working run records identify run/persona/focus, requested/acknowledged/observed model and effort, phase, candidate, execution status, verdict, findings and verification limits. Every selected cell appears, including cancelled, unavailable and no-findings runs. Verification runs remain distinct from independent discovery. Persistent content hashes and committed full-body REVIEW_RUNS.json archives are not required.

## Compact retained evidence

At completion retain readable findings, discovering reviewer/model/effort, shared discovery credit, separate verification credit, original disposition, final correction status, tested revision, initial/final review outcomes and remaining limitations. SUMMARY.md and consolidated REVIEW.md provide this account; a small FINDINGS.json may retain structured details. Requested settings must remain distinguishable from source-observed settings. Retain cancelled/incomplete/no-findings outcomes in a compact roster or counts sufficient to describe actual coverage; never present them as approvals.

Do not embed complete report bodies, repeated source manifests, prior artifact copies or raw command logs into committed JSON. Resolve substantive evidence into a concise trigger, violated expectation, consequence, source location and verification result. Refutations and accepted debt remain explicit. Preserve each contributing reviewer and phase when deduplicating a finding.

Before removing working or previously committed bulky evidence, compare every retained finding/disposition, discovering and verifying actor/model/effort, phase, review outcome and source-backed limitation with the originals. Update current links and remove lookups into deleted archives. When an existing archive is intentionally retired, a stable Git revision may identify its historical content; do not duplicate it into another committed file. Keep unresolved investigation evidence available outside Git until settled.

File-size cleanup does not change model coverage, scope approval, runtime schemas, source facts or delivery gates. Keep required runtime artifacts separate from review bookkeeping.

## Coordinator report and later efficacy analysis

REVIEW.md must include a compact run roster with persona, exact model/effort, phase, revision and completion/verdict, plus each canonical finding's discovering reviewer/model pairs and verification/disposition. Include no-findings and incomplete/failed runs so the denominator is visible. The final user handoff identifies which reviewer/model found confirmed issues, or explicitly says there were no confirmed issues; link the retained findings or summary for detail. Do not report requested identity as observed identity.

For later comparisons, group by persona AND model/effort on equivalent candidate revisions, requirements, tool access and instruction versions. Count each canonical confirmed finding once per group, preserve shared discovery credit, and separately report the union of defects found across groups. Report unique contributions, refuted claims and unresolved candidates separately; do not sum model credits as total unique bugs. Keep discovery, verification and re-review populations separate. Precision can be estimated only over adjudicated candidates with a stated deduplication rule; completion/zero-finding rates need all runs. Recall requires independently labeled defects or a qualified escaped-defect dataset, not absence of reports. Cost/latency comparisons require measured data. No ranking or quality claim from one review, different scopes or a low-cost model merely reporting more candidates.

A confirmed blocker from either model blocks delivery. The gate requires every applicable persona/profile cell to be complete with matching evidence or justified revision carry-forward; one model's approval cannot stand in for the other. Use the parallel protocol's verified findings and revision-aware re-review rules. Re-review affected focuses under both configured profiles; retain original outcomes and credit in the compact history rather than overwriting attribution.

For readable handoff summaries, put the reviewer responsibility and exact observed model/effort beside each concrete finding and fix in SUMMARY.md. Keep shared discovery and verification credit distinct.
