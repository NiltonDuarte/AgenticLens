### Prior A1 / ARCH-07 routing objection — refuted

The earlier objection treated callback JSON `WorkingDirectory` as the operating system process cwd. PO-20 section 3 distinguishes these: the declared harness session context is the routing input; a different callback-process cwd must neither redirect nor invalidate it, while contradictory authoritative session/source evidence must stop capture.

In `backend/cmd/agentic-lens/dispatch.go`, `nativeCodexHook` requires an absolute declared session cwd, resolves the owning shared config from that value, and obtains the selected local policy/project before dispatch. The process cwd is not consulted for project selection. The exact rollout is checked against the configured source store; when `codex.SessionContext` establishes a source cwd, its resolved project must be the same project as the declared session context, otherwise capture returns a conflict error. `NormalizeCodexSubagentStart` likewise validates the parent/child identity and rejects an established cross-project child context while tolerating delayed metadata. Thus the guard implements both process-cwd independence and authoritative-context contradiction rejection; choosing rollout cwd over a conflicting declared context would contradict the approved rule.

`TestNativeDispatcherDisabledSessionUsesContextAndAvoidsCaptureIO` in `backend/cmd/agentic-lens/dispatch_test.go` invokes the real dispatcher with an unrelated process cwd and a different runtime home. The declared session project selects the disabled policy and returns before source/cache/state access. This is direct evidence for process-cwd independence and disabled ordering, not a test of every enabled contradictory-source branch. The latter is supported by the source guard above and existing native source/context evidence. ARCH-07 is therefore correctly recorded as refuted, severity 0; no code change is requested.
