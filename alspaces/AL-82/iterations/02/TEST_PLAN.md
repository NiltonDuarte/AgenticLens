## Extend the existing boundary owners

- **Configuration:** `backend/internal/adapters/config/loader_test.go` and `writer_test.go` already cover explicit YAML values, local selection, source-free reads and YAML-sensitive round trips. Extend these with tags-only local files, per-key shared/local retention, quoted scalar text, non-string values/keys, normalized duplicate keys in each layer and empty maps. Exercise the production loader/writer, including preservation of shared tags when effective local values differ; do not assert only an in-memory map assignment.
- **CLI and publication:** reuse `captureGenerationFixture`, `generation_policy_test.go` and `checkpoint_generate_test.go`. Prove full shared/local/CLI precedence, repeated CLI keys/first-equals parsing and unchanged bytes after invalid input. Start with an accepted tagged ledger, make a genuinely failed summary publication attempt with different effective tags, and assert the prior ledger/tags survive. A failure before any existing ledger is present does not prove preservation. Automatic worker publication needs one real worker-path assertion that shared/local defaults reach root tags while manual flags remain invocation-only. Both Codex and OpenCode generation paths must persist root tags without adding session tags or altering user attribution.
- **Portability and history:** extend generation's source-free canonical/API helper and backfill's `TestBackfillEngine_MultiMachineLifecycle` or source-specific refresh cases. Extend the supported migration fixture with root tags so decoding/transformation cannot silently drop them. Keep all fixtures independent of live ticket artifacts.
- **Whole-ticket API selection:** extend `backend/internal/adapters/http/server_test.go`'s `TestMultiFilterEndpoints` setup. Give one selected ticket multiple owners and distinct code/tokens/cost totals, another ticket a different map, and a third no tags. Assert list, fleet, comparison and progression include complete selected-ticket totals, never a session allocation; detail selection and source-trace separation follow the contract. Cover OR values, AND keys, explicit Missing versus literal `Missing`, legacy no-filter behavior, malformed `tag_filter` returning 400, and existing prefix/date/type composition. Capture source file bytes around GET to prove reads do not rewrite/relabel history.
- **Frontend boundary and recovery:** extend `web/src/api/client.test.ts` for optional legacy tags, malformed maps and the encoded `tag_filter` transport. Extend the Fleet/Progression/Comparison view suites with one empty-to-reset sequence that retains the pre-filter catalog and complete ticket totals. Existing empty/filter controls tests are reusable evidence, not substitutes for the new tag path. Arbitrary literal keys such as `__proto__` and `constructor` must remain ordinary data.
- **Comparison identity:** extend `web/src/components/TicketScatterPlot.test.tsx`. Snapshot point ticket IDs and coordinates before/after tag coloring; assert completion defaults, stable identities through filtering/sorting, neutral absent-key identity distinct from literal `Missing`, legend/tooltip/keyboard labels retaining completion, and existing manual/unavailable-metric exclusions. A literal `Mixed` is ordinary text; contributor Mixed tests are superseded by ticket ownership.
