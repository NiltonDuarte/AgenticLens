# Reported cost and availability

AgenticLens schema v5 distinguishes reported zero from unavailable USD cost. Costs are reported amounts, not verified invoice spend. API-equivalent estimates, rate cards and subscription allocation are not included.

Invocation and task facts contain `cost_usd` and `cost_evidence`. Evidence has `state` (`observed`, `partial`, or `unavailable`) and nullable `known_subtotal_usd`. Observed cost has matching numeric amount and subtotal, including zero. Partial cost has a null complete amount and a numeric known subtotal. Unavailable cost has null amounts. Partial invocation evidence occurs when OpenCode coalesces source records with both reported and missing costs into one model row. New Codex extraction reports unavailable cost because rollout usage does not establish USD cost.

Valid historical numeric values are observed, including historical Codex zero. Missing/null legacy values remain unavailable. This compatibility policy requires no source lookup or additional historical state. A successful explicit source refresh replaces only the recovered owner's snapshot using current source evidence; unavailable trees retain their persisted baseline.

Derived cost fields are nullable complete amounts, paired with `cost_summary`. A summary contains `state` (`empty`, `complete`, `partial`, or `unavailable`), nullable `known_subtotal_usd`, and `fully_observed`, `partial`, `unavailable` and `total` invocation counts. State counts sum to total. A complete amount exists only for a nonempty selection of fully observed facts. Known subtotals include reported contributions of partial facts and are displayed with explicit coverage. Invocation coverage is not financial coverage. Task costs are auxiliary references and do not contribute to invocation totals.

Fleet `total_cost_usd` follows the same rule. `role_costs` and `model_costs` contain nullable amounts with matching `role_cost_summaries` and `model_cost_summaries`. Time buckets expose `cost_summary` and `cumulative_cost_summary`; cumulative complete cost remains unavailable after an unknown contribution. Cost-derived shares require complete nonzero denominators. Otherwise `role_effort_unavailable_reason` explains why a distribution is unavailable. Unrelated non-cost metrics stay usable.

Canonical v4 ledgers remain readable without rewriting or source logs. v1-v3 input requires explicit migration through the existing framework. New generation and persistence target v5. Use the existing migration command's dry-run, ticket filter and backup options; consult the built CLI help for exact options. v4-to-v5 conversion preserves numeric amounts and ownership and does not create a source-recovery requirement solely for missing costs. Pre-v4 shape migrations retain their existing source-recovery requirements.

Old binaries reject v5 files. Preserve migration backups when rollback is needed. JSON consumers must update numeric-only cost assumptions to handle null and the evidence/summary metadata. The bundled frontend updates with the backend; missing costs are not emitted as numeric-zero compatibility values for old clients. Ordinary GET requests do not migrate or rewrite ledgers.

Typed boundary DTOs declare nullable amounts, evidence and summaries explicitly. Standard JSON encoding retains the established relative order of their fields, including nested objects, with cost evidence beside the related amount. Version-specific decoders handle legacy presence and validation without rewriting an arbitrary JSON tree.

Cost KPI cards separate the short amount from availability and coverage details. Partial values are visibly labeled known subtotals; unavailable/empty values use a dash and a clear state. Comparison Average Spend uses complete-cost tickets within the active filters, includes observed zero, and states the eligible ticket count. Partial/unavailable tickets remain in other comparison metrics and rows; they are excluded only from this average and its denominator. Invocation coverage counts retain their existing meaning.

Financial validation follows explicit API/schema locations; dynamic role/model map keys are opaque identifiers. Persisted fact DTOs, compact computed exports and richer HTTP responses remain distinct contracts. Fact-ledger ingestion keeps its required reverse conversions; computed exports are verified as emitted output rather than treated as a second ingestion format. Internal numeric compatibility and per-ledger scalar rounding remain separate from precise cost summaries.
