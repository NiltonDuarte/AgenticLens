# AL-68 Technical Contract

Status: Proposed; implementation requires explicit user approval of this contract and iteration 01 plan.

## Baseline and problem

Specification: alspaces/plan/to-do/AL-68 install harness lifecycle hooks for automatic session capture.md. Baseline: 7bc670a7f5c9e93a220f3596f3d0e05cb6007332. Initial checkout was clean. The coordinator owns branch naming, ticket index and remaining workspace artifacts. Workspace root is the configured alspaces.

Final generation currently discovers one selected source root and its native descendants. Independently launched sessions can be omitted when no native parent exists. AL-68 delivers installation, durable registration, explicit binding, source reconciliation, health diagnostics and final publication together. It must not rely on third-party personas executing final telemetry commands.

## Approved scope proposed

1. Add an AgenticLens-owned lifecycle CLI and release-embedded harness glue. Proposed command family: capture install, capture status, capture receive, capture bind, capture reconcile, capture disable and capture uninstall. Install supports dry run; status, registrations and reconciliation support machine-readable output. Command spellings may be refined without changing these responsibilities.
2. Make the Go binary the canonical owner of hook installation and removal. Integrate it into the existing approved setup flow and keep both downloaders, both shipped wrappers and the documented direct/PowerShell installation path consistent. Downloading a binary alone must clearly distinguish binary readiness from lifecycle readiness. Check handler compatibility before installing configuration; never activate a configuration with an absent handler. Client repositories retain release-only installation and require no new Go or Node toolchain.
3. Register Codex lifecycle callbacks and an OpenCode local plugin using additive, ownership-tracked changes. Preserve unrelated hooks and local edits. Reinstall is idempotent; upgrades replace only unchanged owned content; disable/uninstall and failed setup reverse only owned changes. Missing or incompatible handlers and unsupported, disabled, untrusted or unverified environments remain actionable degraded states.
4. Persist minimal normalized registrations and pending work in an ignored local capture directory, with configured local path override. Record source identity and source-store scope, exact session ID, independently evidenced parent/correlation, binding provenance, event identity, checkpoint and reconciliation status. Do not retain prompts, transcript contents, secrets or unrestricted hook payloads. Persist source errors without sensitive content. Hook delivery performs bounded durable handoff; source extraction occurs during explicit reconciliation/final generation, never inside shutdown handlers. Recovery drains pending work after restart.
5. Bind ownership by an explicit session-specific capture bind operation or proven inherited parent binding. A caller may bind independent reviewer IDs from outside the reviewer session. A directory, branch, role, model, nearby timestamp or interface task ID never grants ticket ownership. Independent unbound sessions are visible and unassigned; their source-backed facts may be captured locally without being published to a guessed ticket. Binding conflicts fail visibly. Correlation metadata never fabricates a native parent.
6. Reconcile every registered session bound to the requested ticket against its actual source, replacing successful cumulative owner snapshots rather than adding repeated totals. Preserve newer accepted snapshots, other roots, other harnesses, unavailable owners and existing persisted facts when access or parsing fails. Known zero activity, pending source flush, failed extraction, unsupported capability and unresolved parent evidence remain separate states. Absence of a native parent does not itself make session capture unsuccessful.
7. Integrate registered roots into final generate while retaining the current explicit nonce/session selection path. Final generation remains a deliberate publication action. Produce the canonical ledger and summary plus a versioned final capture report sidecar, capture_report.json, containing cutoff, capability/coverage status and registered-session outcomes. Bind the report to the produced ledger with a digest; link its coverage limits from SUMMARY.md. Intermediate state stays ignored. This sidecar keeps installation/correlation metadata out of source-derived metric facts and avoids a cross-cutting canonical ledger schema migration. Publication failure must not claim a consistent report/ledger pair. Existing consumers continue to read canonical schema v5. If implementation demonstrates that a canonical schema change is necessary, stop for a revised contract and explicit approval rather than silently introducing v6.
8. Update setup/operator/contributor guidance at its canonical sources, including minimal session binding, diagnostics, trust, recovery, upgrades/removal and support matrix. Keep the adopting AGENTS.md block limited to binding and final publication. No third-party skill/persona edits, T3 telemetry source, T3 dependency or dashboard feature.

## Architecture and fidelity

Pure models and decisions belong under backend/internal/domain, including identity/binding conflict checks, snapshot precedence and coverage evaluation. All clocks, filesystem operations, locks, hook input validation and source reads belong in adapters; command composition belongs under backend/cmd/agentic-lens. Reuse Codex discovery/parsing and OpenCode family dispatch; source family names are not assumed harness version ranges. Exact ownership and per-source replacement must not inherit the OpenCode title/workspace fallback.

Use strict concrete Go/TypeScript types, zero any/interface{}, zero emojis and immutable domain inputs. OpenCode glue runs in its existing runtime with no added runtime dependency. Model, effort, usage and cost derive from authoritative source records when available; unknown values and existing cost evidence remain unknown. Preserve AL-62 skills/task_links snapshots and existing migration behavior. Hooks must not write final artifacts, initiate model calls, recursively invoke hooks or invoke network/self-updating wrappers. Treat payload values as data, use argument-safe native process launch and do not persist full tool inputs/outputs.

Bound handoff by a documented input-size limit and short configurable timeout. Use atomic per-event writes and a crash-safe single-writer reconciliation transaction or equivalent recoverable ownership protocol. Bound each reconcile pass by the selected ticket's registered owners and explicit source byte/session budget; partial work remains pending with a continuation, never complete. Do not rescan every transcript on every lifecycle event. Source flush/revision checkpoints, rather than callback arrival order, govern replacement.

## Capability evidence and support limits

Planning observations on 2026-11-01: codex-cli 0.166.0 is installed and reports hooks stable/enabled; OpenCode reports 1.19.5. These observations do not prove callback execution, identity mapping or successful capture. No real smoke has run. The application binary and frontend dependencies were absent at baseline; current application CLI options were inspected in source, not executed.

The official Codex hooks guide documents parent session_id in subagent callbacks, a separate agent_id, and agent_transcript_path at SubagentStop. Their mapping to source identity requires a real smoke. It also documents trust and local/cloud orchestration differences. This session's T3/native-child path has not been tested; no compatibility claim follows from the documentation. Source: https://learn.chatgpt.com/docs/hooks.

OpenCode documents local plugin event delivery for session creation, updates, status, idle and errors. Installed-version payload shape and source-family behavior require verification independently. Source: https://opencode.ai/docs/plugins/.

Before claiming support, record exact harness version, interface path, platform, enabled/trusted state, observed payload semantics and source-verified native child plus independent-root capture. Evaluate Codex SessionStart, SubagentStart, SubagentStop, Stop and SessionEnd. Evaluate OpenCode creation/update/status/idle/error in each claimed family. Idle/Stop is a checkpoint, never ticket completion. Trust is never auto-approved. Unsupported paths are explicitly degraded; unavailable environments are recorded rather than silently substituted by fixtures.

## Acceptance and completion

Every specification acceptance criterion remains in force. The slice must pass self-contained installer, domain, source, crash/concurrency and publication regressions; real supported-harness parent/child and independent-root smoke evidence; independent focused review; integrated make. Preserve successful baseline ledger reads with all enrichment unavailable. Verify paths with spaces, configured destinations/sources, advertised platform configuration, conflict preservation, rollback and missing binary behavior.

No code or runtime configuration is authorized by planning alone. The parent owns consolidated review, integration, final telemetry, commits and PR delivery. Unavailable required evidence blocks a complete-support claim and must be resolved or explicitly reflected in an approved changed acceptance boundary. Release publishing and merging are outside this contract.
